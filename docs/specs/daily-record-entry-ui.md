# 稼働実績の入力・編集 — UI/画面 仕様

MVP ユースケース1「稼働実績の入力・編集」の **UI/画面** 受け入れ条件。業務仕様は `docs/specs/daily-record-entry.md` が持ち、本仕様はそれと矛盾しない範囲で「入力・編集の画面が満たすべき形」だけを定める。画面骨格・状態×ロールの操作可否・read-only の共通挙動は `docs/specs/work-month-screen-ui.md`（以下「共通仕様」）が持つ。

**業務ルール（値域・未来日・丸め・状態遷移）はこの仕様へ書き写さない。** 正解は `docs/specs/daily-record-entry.md` と `docs/domain/ubiquitous-language.md`。本仕様は参照のみ（ADR 0004）。

- **決定者**: 人間（プロジェクトオーナー）。UI 固有の論点（一覧の表示形態・入力ウィジェット）は人間が決定済み（共通仕様「確定事項」Q4・Q5）
- **日付**: 2026-07-23

---

## スコープ

- **対象**: `Draft` 状態の勤務月画面における、日次実績の**一覧表示・入力・編集・削除**の UI と、その状態（空／入力中／バリデーションエラー／締め後 read-only）
- **非対象**: 締め・承認・差戻しの UI（`monthly-closing-ui.md` / `approval-ui.md`）、画面骨格・状態バッジ・操作可否マトリクス（共通仕様）、勤務月一覧・ログイン（`work-month-listing-ui.md` / `login-ui.md`）

---

## 前提（P）

| # | 前提 | 出典 |
|---|---|---|
| P-1 | 業務ルールは `daily-record-entry.md` に確定済み（1日1レコード、稼働時間直接入力、値域 0〜24時間、未来日不可、当該月外不可、暗黙生成、削除＝空扱い） | `daily-record-entry.md` D-1〜D-8・AC |
| P-2 | 入力・編集・削除は `Draft` 状態かつ技術者本人のみ提供（共通仕様 AC-3） | 共通仕様 |

| AC | 主題 | 出典 |
|---|---|---|

| AC-4 | バリデーションエラー表示 | `daily-record-entry.md` AC-2・AC-3・AC-4 |
| AC-5 | 編集 | `daily-record-entry.md` AC-2-3・AC-5 |

| AC-8 | 限界 | — |

### AC-1. 日次実績一覧の表示

| # | 条件 | 期待 |
|---|---|---|
| 1-1 | 入力済みの日 | 対象日と、その日の稼働時間を一覧に表示する |
| 1-2 | 各日の表示値と総稼働時間 | **整合する**（画面上で各日を足した結果が総稼働時間と一致して見える）。丸め規則により各日は15分単位で切り捨てた寄与として扱われる（`daily-record-entry.md` AC-6／ユビキタス言語「丸め規則」） |
| 1-3 | レコードのない日 | 「稼働なし」として扱い、合計に寄与しない（明示ゼロ表示を強制しない。`daily-record-entry.md` D-5） |
| 1-4 | 一覧の表示形態 | **カレンダー**表示（人間決定 Q4）。日を選んで入力・編集する。入力済みの日と稼働時間が識別でき、総稼働時間と整合すること |

### AC-2. 空状態（実績0件・暗黙生成）

| # | 条件 | 期待 |
|---|---|---|
| 2-1 | 勤務月に実績が1件も無い | 空であることを示し、入力への導線を示す |
| 2-2 | 勤務月がまだ生成されていない年月 | 画面上は空状態と同じに見せる。**「月を開く」等の明示的な生成操作を UI に置かない**（初回入力で暗黙生成。`daily-record-entry.md` D-6・AC-1-5） |
| 2-3 | 初回入力の送信 | 当該 `契約 × 年月` の勤務月が暗黙生成され、その日の実績が一覧に現れる（生成は利用者に追加操作を求めない） |

### AC-3. 入力フォーム

| # | 条件 | 期待 |
|---|---|---|
| 3-1 | 入力項目 | **対象日**と**稼働時間（時・分）**のみ。開始・終了時刻や休憩時間の入力欄を設けない（`daily-record-entry.md` D-2・D-3） |
| 3-2 | 稼働時間の指定 | 時と分を**数値入力**で指定して稼働時間そのものを入力する（人間決定 Q5）。値域・粒度は `daily-record-entry.md` AC-3 が持つ |
| 3-3 | 送信 | 妥当な入力は該当日の実績として反映する。既にレコードのある日への送信は編集として扱う（AC-5） |

### AC-4. バリデーションエラー表示

弾く条件そのものは `daily-record-entry.md`（AC-2〜AC-4）が持つ。本 AC は**画面がどう弾き、どう伝えるか**を定める。エラー時の共通挙動（入力値を失わせない等）は共通仕様 AC-6。

| # | 入力 | 期待 |
|---|---|---|
| 4-1 | 稼働時間が値域外（負値／24時間超／分が0〜59外） | 送信を弾き、値域の理由を提示する（判定は `daily-record-entry.md` AC-3） |
| 4-2 | 対象日が未来日（JST 当日より後） | 送信を弾き、未来日不可の理由を提示する（`daily-record-entry.md` AC-4） |
| 4-3 | 対象日が当該勤務月の年月に属さない | 送信を弾き、理由を提示する（`daily-record-entry.md` AC-2-4） |
| 4-4 | エラー時 | 利用者が入力した対象日・稼働時間を保持し、再入力を強いない（共通仕様 AC-6-2） |

### AC-5. 編集

| # | 条件 | 期待 |
|---|---|---|
| 5-1 | 既にレコードのある日を選ぶ | その日の既存値を初期表示し、編集として扱う（新規作成ではない。`daily-record-entry.md` AC-2-3） |
| 5-2 | 編集の保存 | その日のレコードを上書きし、一覧・総稼働時間に反映する |
| 5-3 | 編集時のバリデーション | 入力時（AC-4）と同一の条件で弾く |

### AC-6. 削除

| # | 条件 | 期待 |
|---|---|---|
| 6-1 | ある日のレコードを削除する | 一覧からその日を取り除き、その日は空状態（「稼働なし」）に戻る（`daily-record-entry.md` AC-5-4・D-5） |
| 6-2 | 削除後 | 明示的なゼロ記録を残さない。総稼働時間からその日の寄与が消える |

### AC-7. 締め後 read-only

| # | 状態 | 期待 |
|---|---|---|
| 7-1 | `PendingApproval` / `Approved` | 入力フォーム・編集・削除の操作要素を提供しない（共通仕様 AC-5）。日次実績一覧は閲覧できる |
| 7-2 | 差戻しで `Draft` に戻った後 | 入力・編集・削除を再び提供する（`approval.md` AC-6-2） |

### AC-8. 限界 — 本仕様が担保しないこと

| # | 内容 |
|---|---|
| 8-1 | 締め・承認・差戻しの UI は対象外（`monthly-closing-ui.md` / `approval-ui.md`） |
| 8-2 | 一覧の表示形態（カレンダー）・稼働時間の入力ウィジェット（時・分の数値入力）は人間決定済み（共通仕様「確定事項」Q4・Q5） |
| 8-3 | 勤務月一覧・ログイン・認証は別 spec（`work-month-listing-ui.md` / `login-ui.md`）が持つ |
| 8-4 | デザイントークン・具体レイアウトは ADR 0015 のデザイン工程が担う |
