# 契約一覧 — UI/画面 仕様

ADR 0021 決定1 が加えた閲覧系の画面「契約一覧」の UI/画面 受け入れ条件。技術者が**自分の**契約を閲覧する画面である。契約は与件であり、勤務月の集約の外にある（ADR 0021 決定2）。本画面は契約のデータを読むだけで、契約を作らず、変えず、消さない。

業務ルール・ユビキタス言語は**この仕様へ書き写さない**ものとする。正解は ADR 0021 決定2、各業務仕様、`docs/domain/ubiquitous-language.md`。本仕様は「契約一覧の画面が満たすべき形」だけを定める（ADR 0004）。

- **決定者**: 人間（プロジェクトオーナー）。画面があること・自分の契約だけを見ること・読む項目（契約表示名・精算幅・契約期間・技術者）・契約の管理を作らないこと・契約期間を年月の範囲で表し終了の定まらない契約を許すこと・契約期間を表示にだけ使うことは人間決定（ADR 0021 決定1・決定2）。「今月の状態」の列を採ること、その「今月」を JST の当月とすること、そのロールで開けない画面を開いたときにそのロールの既定の画面へ移すことは、2026-10-10 の人間決定である（後者の条文の正は `login-ui.md` AC-6-7〜6-9-b）。今月の勤務月がまだ生成されていない契約に `下書き` と示すこと（2-5-c）は、2026-10-13 の人間決定である
- **日付**: 2026-10-10（2026-10-13 改定: 2026-10-10 の人間決定を反映し、契約期間の表示・今月の状態の列・開けないロールが開いたときの扱いを定め、未確定点を解消。同日の人間決定を 2-5-c に反映した。同日の人間決定により、AI 起案の箇所をすべて人間の承認済みへ改めた）。2026-10-21 改定: ドメイン API に契約一覧の読む口（E-8）が足されたため、7-3 の「読む口が揃っていない」という事実の記述を現況へ改めた（画面の要求は変えていない）
- **前提 ADR**: 0021（閲覧系の画面・元データ）／0016（認証・ロール・ゲスト）／0015（デザイン工程）
- **AI 起案の扱い**: 条文中に「AI 起案（2026-10-13 に人間が承認）」と書いた箇所は、AI が起案し、2026-10-13 に人間が一括で承認したものである。承認済みであり、その箇所をテストの期待値にしてよい

## スコープ

- **対象**: 契約一覧に載せる契約の範囲、各行の表示（契約期間・今月の状態を含む）、勤務月一覧への遷移、閲覧のみであること、開ける利用者、空状態・エラー
- **非対象**:
  - 契約の管理（作成・変更・削除）。画面も操作も作らない（ADR 0021 決定1）
  - 契約のデータの投入の手段（デモデータとして投入する。手段は実装工程が決める。ADR 0021 決定2）。ログインした技術者の契約を自動で用意する手段も本仕様の対象外である（`engineer-contract-provisioning.md`。ADR 0023。提案中）
  - 契約期間と勤務月の対象年月の整合の検査（行わない。契約期間は表示にだけ使い、検査は将来の検討事項とする。ADR 0021 決定2・「将来の検討事項」／`workmonth-implementation-design.md` AC-13-9／`domain-api-http-contract.md` AC-11-5）
  - サイドバーの項目（`work-month-listing-ui.md` AC-10 が持つ）・ヘッダー（`login-ui.md` AC-9 が持つ）
  - 遷移先の本人の勤務月一覧と、その絞り込み（`work-month-listing-ui.md` AC-1・AC-9 が持つ）
  - そのロールで開けない画面から既定の画面へ移すこと（`login-ui.md` AC-6-7〜6-9-b が持つ。本仕様は契約一覧に当てはめた結果だけを AC-5 に示す）
  - 技術者の横断ビュー（他の技術者の契約・稼働を見る画面。非スコープのまま。ユビキタス言語「MVP スコープ外」）
  - デザイントークン・具体レイアウト（`design-system.md`）

### AC-7. 限界 — 本仕様が担保しないこと

| # | 内容 |
|---|---|
| 7-1 | 契約一覧の精算幅（契約のいまの値）と、作成済みの勤務月の精算幅（生成時の複写）が食い違いうることを、本画面は解消しない。食い違いは「契約変更が過去の勤務月に遡及しない」（ユビキタス言語【確定】）の帰結であり、不具合ではない |
| 7-2 | 契約期間の外の年月にも勤務月を作れる既存の帰結（`workmonth-implementation-design.md` AC-13-9）は残る。本画面に契約期間と今月の状態が並ぶことで、期間が過ぎた契約にも今月の状態（未生成なら `下書き`。2-5-c・2-5-d）が出るなど、食い違いが目に付きやすくなる（ADR 0021「悪い影響 / トレードオフ」）。整合の検査を足すかは ADR 0021「将来の検討事項」である |
| 7-3 | 契約のデータ（契約期間を含む）と、契約ごとの今月の勤務月の状態は、ドメイン API の契約一覧（`domain-api-http-contract.md` E-8・AC-12・AC-10-4）から1回の呼び出しで読む（2026-10-21 の人間決定。同ファイル決定8〜決定10）。「今月」の年月は画面の側が 2-5-a のとおり決めて渡し、API は渡された年月の状態を返す。未生成の今月は `state: "Draft"`・`generated: false` で返る（同 AC-12-7。2-5-c の `下書き` の根拠）。契約一覧の API は技術者本人（`Engineer`）だけに応答し、承認者・ゲストには 403・401 を返す（同 D-20）。BFF の経路は `bff-wiring.md` の R-10 |
| 7-4 | 表の列幅・余白・狭い画面での配置は画面固有の合成であり、`design-system.md` AC-5 の 5-3（「契約一覧の表」）のとおり画面 Issue が持つ |
| 7-5 | 技術者の横断ビューを**提供しない**ものとする。本画面は本人の契約に限る（1-2） |
| 7-6 | 今月の状態は表示した時点の値である。開いたまま JST の月が替わった・他の経路で状態が変わったときに、表示を自動で改めることは要求しない（開き直すと 2-5-a のとおり改まる） |
