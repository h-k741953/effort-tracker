# README の同期 — ADR 0013 / 0014 / 0016 基準へ現況を反映する

Issue #58 の仕様。README.md が**廃止済みの ADR 0005（Vercel → AWS の OIDC Federation）と Vercel ホスティング前提の記述を残したまま**であり、ADR 0013 / 0014 と矛盾している。あわせて ADR 一覧が 0008 で止まり、ADR 0016（Cognito）が未反映である。この README を最新の決定へ同期するための**受け入れ条件**を定める。

**本仕様は `docs/specs/security-rules.md` の「非スコープ」および AC-5-4 が別 Issue へ送った残留を引き取るものである。** #57 は `docs/rules/security.md` を ADR 0013 / 0014 基準へ同期する際、README を意図的に非スコープとし、「この同期の完了後も `docs/rules/` と README が食い違う状態が残る」と明記した。その残留の解消先が本仕様であり、本仕様の完了をもって当該 AC-5-4 の残留は閉じる。

**新たな技術選定ではなく、決定済み事項の同期および加筆である。したがって ADR は起こさない。** 決定の本文（なぜ AWS ネイティブなのか・なぜ実行ロールなのか・なぜ Cognito なのか）はこの仕様へ書き写さない。正解は `docs/adr/0013-aws-native-hosting-over-vercel.md` / `docs/adr/0014-execution-role-over-vercel-oidc.md` / `docs/adr/0016-cognito-end-user-authentication.md` にあり、本仕様はそれを参照して「README が満たすべき形」だけを定める（ADR 0004）。

### 非スコープ

- **README.md の書き換えそのもの。** 本仕様は受け入れ条件のみを定める。実装は別の `task` Issue で行う（AC-8-6）
- **ADR 本文の書き換え。** 廃止 ADR も含め本文は書き換えず追記もしない（ADR 0001 運用ルール3）。ADR 0003 のステータス行が廃止済みの ADR 0005 に言及している点も**据え置く**（実測）
- **`docs/rules/` の再同期。** #57 で ADR 0013 / 0014 基準へ同期済みであり（P-2）、本仕様では触らない
- **`docs/rules/notation.md` の文言の明確化。** 「中身を書き換える既存図」が『今後書く図』か『既存の書き換え』かを規約は明示していない。今回は個別判断で通す（P-5）が、規約側の明確化は本仕様で行わない
- **ADR 一覧の同期を機械検査する仕組みの新設。** 論点4 で 4-a（一覧を残す）を採ったため、同期は手作業のまま残る（AC-8-2）。取り消し線の規則を一般化しても（AC-5-5）、**行の追加漏れは手作業のまま**である（AC-8-8）
- **A〜D に該当しない ADR の内容を README 本文へ反映すること。** 例として ADR 0015（Claude Design）や 0009〜0012（ハーネス系）は、**ADR 一覧への追記（C）に留め**、技術スタック表や各節への反映は本仕様の対象外とする
- **Terraform / Cognito / `apps/web` の実装**（Issue #8 / #52 / #9）、および**デモURL の公開そのもの**

## 前提（P）

### P-1. 決定は ADR 0013 / 0014 / 0016 で確定済み

本仕様は新たな技術選定・業務ルールを決めない。既に承認済みの決定を README という読み口へ写すだけである。したがって AC は「どう決めるか」ではなく「README が決定を正しく写しているか」だけを問う。

### P-2. 食い違っているのは README だけである

`docs/rules/` 側は既に現況へ同期済みである（実測）。`security.md` は #57 で ADR 0014 基準（CI は GitHub OIDC、ランタイムは実行ロール）へ、`cost-guardrails.md` は CloudFront / Budget Actions を含む ADR 0013 前提へ、`architecture.md` は BFF Lambda 前提へ更新されている。**README を rules に合わせるのであって、その逆ではない。**

### P-3. Issue #1 は CLOSED であり、結論は ADR 0013 が持つ

README は3箇所（現行 L26 / L88 / L255）で Issue #1 を「未決の根拠」として参照するが、#1 は ADR 0013 で決着してクローズ済みである。**「保留中」という記述自体が事実と異なる。**

### P-4. README は利用者向けの入口であり、意思決定の履歴を置かない

ADR 0001 のコンテキストは、判断の記録先として README を検討し「読者は利用者。意思決定の履歴を置くと肥大化して本来の役割を果たさなくなる」として却下している。論点2 の 2-a はこの立場と整合する。**経緯という成果物は失われない** — 保留から決着までの経緯は ADR 0005 / 0013 / 0014 に既に記録されており、README はそこを参照するだけでよい（ADR 0004）。

### P-5. アーキテクチャ図の mermaid 化は「新規扱い」とする個別判断である

`docs/rules/notation.md` は「既存の図（ASCII アート）を mermaid へ書き換えない」と書く。一方、据え置きの**根拠は ADR 0001 運用ルール3、すなわち ADR 本文の不可変性**である（ADR 0010 §G、および同 ADR が却下案として挙げた「既存 ADR も mermaid に書き換える」）。README は ADR ではなく、かつ当該図は内容自体が事実と異なるため書き直しになる。以上から、**今回に限り新規の図として mermaid で書く**（論点3 = 3-b）。

**この判断は規約の文言から機械的に導かれたものではない。** 規約側の曖昧さは解消せず、非スコープとして残す（AC-8-4）。

### P-6. 実装は未着手であり、「未完了」の記述は現況として真である

`infra/` および `apps/` はディレクトリごと存在しない（実測）。したがって README の「デモURL 未公開」「インフラ未着手」「`apps/web` 未スキャフォールド」「Next.js / TypeScript の版が未定」は**いずれも現況として真**であり、本仕様はこれらを書き換えない。**同期を口実に未完了を隠さない**（AC-3-4）。
