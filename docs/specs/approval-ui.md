# 承認申請・承認 — UI/画面 仕様

MVP ユースケース3「承認申請・承認」の **UI/画面** 受け入れ条件。業務仕様は `docs/specs/approval.md` が持ち、本仕様はそれと矛盾しない範囲で「承認・差戻し操作の画面が満たすべき形」だけを定める。画面骨格・状態×ロールの操作可否・状態表示・read-only の共通挙動は `docs/specs/work-month-screen-ui.md`（以下「共通仕様」）が持つ。

**業務ルール（承認・差戻し可否・認可・自己承認排除・終端性）はこの仕様へ書き写さない。** 正解は `docs/specs/approval.md` と `docs/domain/ubiquitous-language.md`。本仕様は参照のみ（ADR 0004）。

- **決定者**: 人間（プロジェクトオーナー）。承認対象への到達手段は人間が決定済み（承認待ち一覧を設ける。AC-8／`work-month-listing-ui.md`）
- **日付**: 2026-07-23

---

## スコープ

- **対象**: 勤務月画面における**承認（`Approve`）・差戻し（`Reject`）操作**の UI と、その状態（承認可能／自己承認排除／承認済 read-only／差戻し後）、承認状態の可視性
- **非対象**: 締め・入力編集の UI（`monthly-closing-ui.md` / `daily-record-entry-ui.md`）、画面骨格・操作可否マトリクス（共通仕様）、**承認者の割り当て・ロール管理**（`approval.md` AC-9-5、非スコープ）

---

## 前提（P）

| # | 前提 | 出典 |
|---|---|---|
| P-1 | 承認・差戻しは `PendingApproval` かつ承認者ロール保持者のみ提供。自己承認は排除 | 共通仕様 AC-3／`approval.md` AC-1〜AC-4 |
| P-2 | 承認済は終端。以降いかなる状態変更操作要素も提供しない | 共通仕様 AC-5-2／`approval.md` AC-7 |
| P-3 | 差戻しは理由コメントを持たない（勤務月に記録しない） | `approval.md` D-3・AC-6-4 |
| P-4 | 「誰が承認したか」を勤務月に保持しない（表示もしない） | `approval.md` AC-5-4 |

|---|---|---|

| AC-2 | 差戻しに理由コメント欄を設けない | `approval.md` D-3・AC-6-4 |
| AC-3 | 自己承認排除の UI 表現 | `approval.md` D-4・AC-4 |
| AC-4 | 承認後の帰結表示（終端） | `approval.md` AC-5・AC-7 |
| AC-5 | 差戻し後の帰結表示 | `approval.md` AC-6 |
| AC-6 | 承認状態の可視性 | `approval.md` D-6・AC-8 |
| AC-7 | 通知 UI の不在 | `approval.md` D-5・AC-8-3 |
| AC-8 | 承認対象への到達手段（承認待ち一覧） | `approval.md` AC-8-2／`work-month-listing-ui.md` |

### AC-1. 承認・差戻しボタンの提供条件

| # | 状態・操作者 | 期待 |
|---|---|---|
| 1-1 | `PendingApproval` かつ承認者ロール保持かつ本人でない | 承認・差戻しの操作要素を**提供する**（`approval.md` AC-1-1・AC-2-1・AC-3-1） |
| 1-2 | `PendingApproval` かつ承認者ロールを持たない（技術者等） | 提供しない（`approval.md` AC-3-2） |
| 1-3 | `Draft` | 提供しない（まだ締められていない。`approval.md` AC-1-2・AC-2-2） |
| 1-4 | `Approved` | 提供しない（終端。`approval.md` AC-1-3・AC-2-3・AC-7） |
| 1-5 | 承認の成立 | 承認者1人の承認で承認済に至る（複数承認者の全員承認を UI で求めない。`approval.md` AC-3-3・D-2） |

### AC-2. 差戻しに理由コメント欄を設けない

| # | 条件 | 期待 |
|---|---|---|
| 2-1 | 差戻し操作 | **理由コメントの入力欄を設けない**（差戻しは状態を戻すだけ。`approval.md` D-3・AC-6-4）。差戻しの実行に理由入力を要求しない |

### AC-3. 自己承認排除の UI 表現

| # | 条件 | 期待 |
|---|---|---|
| 3-1 | 操作者が承認者ロールを持ち、かつその勤務月の技術者本人（`PendingApproval`） | 承認・差戻しの操作要素を**提供しない**（非表示で統一。共通仕様 AC-3・人間決定 Q8）。ロールに依存せず維持する（`approval.md` D-4・AC-4-1／ADR 0016） |
| 3-2 | 操作者が承認者ロールを持ち、本人でない | 承認・差戻しを提供する（AC-1-1）。可否は状態とロールのみで決まる（`approval.md` AC-4-2） |

### AC-4. 承認後の帰結表示（終端）

| # | 承認成立後 | 期待 |
|---|---|---|
| 4-1 | 状態バッジ | `Approved` を表示する（`approval.md` AC-5-1） |
| 4-2 | 操作要素 | 承認・差戻し・締め・入力編集のいずれも**提供しない**（終端 read-only。共通仕様 AC-5-2／`approval.md` AC-7） |
| 4-3 | 保持値の表示 | 総稼働時間・超過／不足を締め時の値のまま表示する（`approval.md` AC-5-2） |
| 4-4 | 承認者情報 | 「誰が承認したか」を**表示しない**（保持しないため。`approval.md` AC-5-4） |

### AC-5. 差戻し後の帰結表示

| # | 差戻し成立後 | 期待 |
|---|---|---|
| 5-1 | 状態バッジ | `Draft` を表示する（`approval.md` AC-6-1） |
| 5-2 | 技術者本人の操作 | 稼働実績の入力・編集・削除を**再び提供する**（`approval.md` AC-6-2。詳細は `daily-record-entry-ui.md` AC-7-2） |
| 5-3 | 差戻し理由 | **表示しない**（記録しないため。`approval.md` D-3・AC-6-4） |
| 5-4 | 差戻し回数 | 上限を設けず、回数を表示しない（`approval.md` AC-6-5） |

### AC-6. 承認状態の可視性

| # | 条件 | 期待 |
|---|---|---|
| 6-1 | 技術者が自分の勤務月の状態を確認 | **既存の勤務月画面の状態バッジで**確認する（`Draft` / `PendingApproval` / `Approved`。`approval.md` D-6・AC-8-1／共通仕様 AC-2） |
| 6-2 | 承認済の勤務月を横断する専用一覧画面 | **設けない**（集約をまたぐ参照系で非スコープ。`approval.md` AC-8-2） |

### AC-7. 通知 UI の不在

| # | 条件 | 期待 |
|---|---|---|
| 7-1 | 締め・承認・差戻しの発生 | 承認者・技術者へのプッシュ通知・メール等の通知 UI を**設けない**（`approval.md` D-5・AC-8-3）。状態は画面を開いて確認する |

### AC-8. 承認対象への到達手段（承認待ち一覧）

| # | 条件 | 期待 |
|---|---|---|
| 8-1 | 承認者が `PendingApproval` の勤務月へ到達する手段 | **承認待ち一覧を設ける**（人間決定 Q2）。`PendingApproval` の勤務月のみを載せ、承認済は載せない（`approval.md` AC-8-2 の承認済一覧禁止は維持）。年月降順・ページングあり（Q6）。仕様は `work-month-listing-ui.md` が持つ |

### AC-9. 限界 — 本仕様が担保しないこと

| # | 内容 |
|---|---|
| 9-1 | 締めの UI は対象外（`monthly-closing-ui.md`） |
| 9-2 | 承認取消しの UI は存在しない（承認済は終端。`approval.md` AC-7-4・AC-9-2） |
| 9-3 | 承認者の割り当て・ロール管理の UI は非スコープ（`approval.md` AC-9-5）。本仕様は「承認者ロールを持つ者が承認・差戻しできる／自己承認は排除する」振る舞いの画面表現のみを定める |
| 9-4 | 承認対象への到達手段（AC-8）は `work-month-listing-ui.md`、認証・現在ユーザーの決定は `login-ui.md`（ADR 0016）が持つ |
| 9-5 | デザイントークン・具体レイアウトは ADR 0015 のデザイン工程が担う |
