# 勤務月一覧 — UI/画面 仕様

勤務月画面（`work-month-screen-ui.md`）へ到達するための**一覧画面**の UI/画面 受け入れ条件。3つの閲覧面を対象とする——技術者本人の「**自分の勤務月一覧**」、承認者の「**承認待ち一覧**」、ゲスト（未ログイン）の「**デモ用サンプル勤務月群（読み取り専用）**」。いずれも人間が決定した到達手段（`work-month-screen-ui.md` 確定事項 Q1・Q2・Q6、および旧 N-1）を具体化する。

**業務ルール・状態遷移・ユビキタス言語はこの仕様へ書き写さない。** 正解は各業務仕様と `docs/domain/ubiquitous-language.md`。本仕様は「一覧画面が満たすべき形」だけを定める（ADR 0004）。

- **決定者**: 人間（プロジェクトオーナー）。到達手段・並び順・ページング・ゲスト導線・自己承認一覧の扱いは人間決定（Q1・Q2・Q6・旧 N-1/N-3・自己承認一覧）。**AI が業務判断を足さない**
- **日付**: 2026-07-25
- **前提 ADR**: 0016（認証・ロール・ゲスト）／0015（デザイン工程）

---

## スコープ

- **対象**: 自分の勤務月一覧（本人分のみ）、承認待ち一覧（承認者向け）、ゲスト向けデモ勤務月群（読み取り専用）、これらの並び順・ページング、一覧から勤務月画面への遷移、本人一覧の直近を既定で開く導線
- **非対象**:
  - 勤務月画面本体（`work-month-screen-ui.md`）
  - ログイン・認証・現在ユーザー／ロールの決定・デモ用ロール切替（`login-ui.md`／ADR 0016）
  - **承認済の一覧化**（`approval.md` AC-8-2 の禁止を維持。設けない）
  - **技術者の横断ビュー**（他の技術者の稼働を横断する参照。非スコープのまま。ユビキタス言語）
  - デザイントークン・具体レイアウト（ADR 0015 のデザイン工程）

## 前提（P）

| # | 前提 | 出典 |
|---|---|---|
| P-1 | 集約は `WorkMonth` の1つ。一覧は集約をまたぐ参照系だが、**本人一覧は本人分に限り**、横断ビュー（他技術者の稼働）ではない | ユビキタス言語「勤務月の同一性」 |
| P-2 | データ取得は BFF（Route Handler）経由。ブラウザは Lambda を直接呼ばない | `docs/rules/architecture.md`／ADR 0016 |
| P-3 | 状態は `Draft` / `PendingApproval` / `Approved`。承認待ち一覧が対象とするのは `PendingApproval` のみ | ユビキタス言語「状態遷移」／`approval.md` AC-1 |
| P-4 | 承認者は承認者ロール保持者。承認・差戻しの可否・自己承認排除は勤務月画面側（`approval-ui.md`・共通仕様 AC-3）が担う | ADR 0016／`approval.md` |
| P-5 | デモデータは日次リセットされる（ゲスト向けデモ勤務月群を含む） | `docs/rules/cost-guardrails.md`（デモデータ 日次リセット） |

### AC-1. 自分の勤務月一覧（本人分のみ）

| # | 条件 | 期待 |
|---|---|---|
| 1-1 | 技術者としてログイン中の利用者 | **自分が技術者である勤務月のみ**を一覧に載せる（掛け持ちで複数契約の勤務月を持ちうる）。他の技術者の勤務月は載せない（横断ビュー非スコープ。P-1） |
| 1-2 | 各行の表示 | 勤務月を識別できる情報（**契約表示名** × 対象年月。共通仕様 AC-1-1・Q9）と状態バッジ（`Draft` / `PendingApproval` / `Approved`。共通仕様 AC-2）を示す |
| 1-3 | 状態による除外 | 状態で行を除外しない（本人の全勤務月を状態にかかわらず載せる。承認済も本人は自分の画面で確認する。`approval.md` D-6・AC-8-1） |

### AC-2. 承認待ち一覧（承認者向け）・自己承認一覧の扱い

| # | 条件 | 期待 |
|---|---|---|
| 2-1 | 承認者ロール保持者 | 承認待ち一覧を表示する。**`PendingApproval` の勤務月のみ**を載せる（P-3。承認者の到達手段。人間決定 Q2） |
| 2-2 | 承認済（`Approved`）・下書き（`Draft`） | **載せない**（`approval.md` AC-8-2 の承認済一覧禁止を維持。承認待ち以外は承認者の到達対象でない） |
| 2-3 | 各行の表示 | 勤務月を識別できる情報（契約表示名 × 対象年月）を示す。承認待ちであることが分かる |
| 2-4 | 承認者ロールを持たない利用者 | 承認待ち一覧への導線を提供しない（非表示。共通仕様 AC-3 の「提供しない＝非表示」に倣う） |
| 2-5 | 自己承認一覧の扱い（確定） | **一覧では絞らず、遷移先で排除する**（人間決定。あなたの暫定案を確定）。自分が技術者である `PendingApproval` の勤務月も承認待ち一覧に載せ、開いた勤務月画面で承認・差戻しを非表示にする（自己承認排除 `approval.md` D-4／`approval-ui.md` AC-3 を維持）。一覧は到達手段であり、操作可否は遷移先で判定する |

### AC-3. ゲスト向けデモ勤務月群（読み取り専用）

ゲスト（未ログイン）の閲覧導線。**デモ用サンプルを読み取り専用で提示する**（人間決定・旧 N-1）。

| # | 条件 | 期待 |
|---|---|---|
| 3-1 | ゲスト（未ログイン）でアプリに入ったとき | **デモ用のサンプル勤務月群**を提示する。各状態（`Draft` / `PendingApproval` / `Approved`）の例を含み、体験として3ユースケースの見え方が分かる |
| 3-2 | 閲覧の性質 | **読み取り専用**。行から勤務月画面へ遷移でき、遷移先はゲスト＝全操作を非表示（共通仕様 AC-3 ゲスト行） |
| 3-3 | 本人一覧・承認待ち一覧との関係 | それらは**ゲストの導線ではない**（本人一覧は本人前提、承認待ち一覧は承認者前提）。ゲストは本デモ勤務月群のみを閲覧する |
| 3-4 | `approval.md` AC-8-2（承認済一覧禁止）との関係 | 本デモ群は**実データの承認済横断一覧ではなく、デモ用サンプル**であり、AC-8-2 の禁止（実運用の承認済一覧）と矛盾しない。技術者の横断ビュー禁止とも矛盾しない（実技術者の稼働横断ではない） |
| 3-5 | デモデータ | 日次リセットされる（P-5／`docs/rules/cost-guardrails.md`） |

### AC-4. 並び順・ページング（本人・承認待ちの両一覧）

| # | 条件 | 期待 |
|---|---|---|
| 4-1 | 既定の並び順 | **対象年月の降順**（新しい月が上。人間決定 Q6）。本人一覧・承認待ち一覧の両方に適用する |
| 4-2 | ページング | **ページングを設ける**（人間決定 Q6）。1ページあたりの件数は**仕様で固定しない**（業務要件なし。デザイン／実装工程の詳細に委ねる。人間決定・旧 N-3） |
| 4-3 | 並び替えの追加軸 | 既定（年月降順）以外の並び替え軸は本仕様では要求しない（追加はスコープ拡大） |

### AC-5. 一覧から勤務月画面への遷移

| # | 条件 | 期待 |
|---|---|---|
| 5-1 | 一覧の行を選ぶ | その勤務月（`契約 × 年月`）の勤務月画面（`work-month-screen-ui.md`）へ遷移する |
| 5-2 | 遷移先での操作可否 | 状態×ロール（ゲスト含む）で決まる（共通仕様 AC-3）。一覧は到達手段であり、操作可否を一覧側で判定しない |

### AC-6. 直近を既定で開く導線（本人一覧）

| # | 条件 | 期待 |
|---|---|---|
| 6-1 | 技術者本人がアプリに入ったとき | **直近の勤務月を既定で開く導線**を提供する（人間決定 Q1）。毎回一覧から選ばせない |
| 6-2 | 勤務月が1件も無い技術者 | 既定で開く対象が無い。空状態（AC-7）を示し、初回入力の導線へ繋ぐ（暗黙生成は `daily-record-entry-ui.md` AC-2） |
| 6-3 | 「直近」の定義 | 対象年月が最も新しい本人の勤務月（AC-4-1 の並びの先頭）。業務ルールではなく並び順の帰結として定める |

### AC-7. 空状態・エラー

| # | 条件 | 期待 |
|---|---|---|
| 7-1 | 一覧に該当が0件（本人一覧） | 空であることを示し、初回入力の導線を示す（`daily-record-entry-ui.md` AC-2） |
| 7-2 | 承認待ちが0件 | 「承認待ちなし」を示す（空一覧を提示。通知はしない。`approval.md` D-5） |
| 7-3 | 取得エラー | エラーを提示し、破壊的な状態変化を伴わない（共通仕様 AC-6-3 に準ずる） |

### AC-8. 限界 — 本仕様が担保しないこと

| # | 内容 |
|---|---|
| 8-1 | **承認済の（実データ）一覧化を行わない**（`approval.md` AC-8-2 の禁止を維持）。承認済は技術者が自分の勤務月画面で確認する（`approval.md` D-6・AC-8-1）。ゲスト向けデモ群（AC-3）はサンプルであり実データ一覧ではない |
| 8-2 | **技術者の横断ビュー（他技術者の稼働横断）を提供しない**（非スコープのまま。ユビキタス言語）。本人一覧は本人分に限る |
| 8-3 | **デモ用ロール切替の UI は本仕様の対象外**（`login-ui.md` が持つ。ADR 0016） |
| 8-4 | デザイントークン・具体レイアウト・1ページの件数（AC-4-2）はデザイン／実装工程が担う |

---

**残存する未確定点は無い**（旧 N-1〜N-3・自己承認一覧の扱いはいずれも人間決定済み。上記 AC-2-5・AC-3・AC-4-2 に反映）。
