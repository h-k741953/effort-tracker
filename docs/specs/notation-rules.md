# 表記ルール — セッション回答は日本語／図は mermaid（Rules への明文化）

Issue #20 の仕様。ADR 0010 §G の決定を、`docs/rules/` に明文化する規約本文の**受け入れ条件**に落とす。根拠は `docs/adr/0010-harness-engineering.md` §G。

**決定の本文（なぜそう決めたか）はこの仕様へ書き写さない。** 正解は ADR 0010 §G にあり、本仕様はそれを参照して「規約本文が満たすべき形」だけを定める（ADR 0004）。依存 #13（規約の `docs/rules/` 切り出し）は完了済みであり、その構成の上に載せる。

---

## スコープ

`docs/rules/` に**表記ルールの規約本文を追加する**こと、および CLAUDE.md からの `@import`・`docs/rules/README.md` 一覧への登録までを対象とする。

明文化する規則は ADR 0010 §G が定める次の2つに限る。これ以外を足さない。

1. **セッション上のエージェント回答（会話・ターミナル出力）を日本語に統一する**（応答言語の振る舞いルール。docs の記述言語の話ではない）
2. **図は mermaid 記法**。ただし**今後書く docs にのみ適用**し、既存 ADR は据え置く（ADR 0001 の書き換え禁止に従う）

### 非スコープ

- 既存 ADR / docs 内の ASCII アート図を mermaid へ書き換えること（ADR 0001 運用ルール3「ADR は書き換えず、追記もしない」に抵触する。当面 ASCII と mermaid が混在する）
- 応答言語・図法を CI やツールで機械強制すること（AC-5 の限界を参照）

---

## 前提（P）

### P-1. 決定は ADR 0010 §G で確定済み

本仕様は新たな業務ルール・技術選定を決めない。ADR 0010 §G が確定させた2つの表記ルールを、Rules 層（`docs/rules/`）で読める形に明文化するだけである。したがって本仕様の AC は「どう決めるか」ではなく「規約本文が決定を正しく写しているか」だけを問う。

### P-2. Rules の構成は #13 が確立済み

規約の実体は `docs/rules/` にあり、CLAUDE.md からは `@import` で参照される（`docs/rules/README.md`・ADR 0010 §B）。表記ルールもこの構成に従い、`.claude/` 側や CLAUDE.md 本体へコピーを作らない。

## 受け入れ条件（AC）

| AC | 主題 | 主に効く工程 |
|---|---|---|
| AC-1 | 表記ルールの規約本文を `docs/rules/notation.md` として置く | implementer・reviewer |
| AC-2 | 応答言語ルールを「応答の振る舞い」として明記し、docs の記述言語と区別する | implementer・reviewer |
| AC-3 | mermaid ルールを「今後の docs のみ・既存据え置き」として明記する | implementer・reviewer |
| AC-4 | CLAUDE.md の `@import` と README 一覧へ登録し、二重管理を作らない | implementer・reviewer |
| AC-5 | 機械検査できる範囲と、できない限界を固定する | tester・reviewer |

### AC-1. 規約本文の置き場所

- 表記ルールの本文を **`docs/rules/notation.md`** に置く。既存の規約ファイル（`scope.md` 等）へ混ぜない。表記は独立した関心事であり、1ファイル1関心の既存構成に合わせる
- 本文の冒頭で **ADR 0010 §G を根拠として参照する**。決定の理由（なぜ日本語か・なぜ既存据え置きか）は ADR 側にあるものとして書き写さない（ADR 0004）

### AC-2. 応答言語ルールの記述

`docs/rules/notation.md` は次を満たす文を含む。

- **セッション上のエージェント回答（会話・ターミナル出力）を日本語に統一する**と明記する
- これが **docs の記述言語の規則ではなく、応答の振る舞いの規則である**ことを、区別が読み取れる形で書く（ADR 0010 §G が両者を別対象として分けているため）

### AC-3. mermaid ルールの記述

`docs/rules/notation.md` は次を満たす文を含む。

- **図は mermaid 記法で書く**と明記する
- この規則が **今後書く docs にのみ適用され、既存 ADR / docs は据え置く**ことを明記する
- 据え置く根拠として **ADR 0001 の書き換え禁止（運用ルール3）** に触れる。当面 ASCII と mermaid が混在することを許容と分かる形で書く

### AC-4. 参照経路の登録（二重管理を作らない）

- **CLAUDE.md に `@docs/rules/notation.md` を追加**し、既存の `@import` 群に並べる。規約本文を CLAUDE.md へコピーしない（`docs/rules/README.md`・ADR 0004）
- **`docs/rules/README.md` の「一覧」表に `notation.md` の行を追加**する。表と実ファイルをずらさない

### AC-5. 機械検査の範囲と限界

**検査できるのは「規約本文と参照が存在すること」までである。** 規則が実際に守られているか（応答が日本語か・新規 docs の図が mermaid か）は、この仕様では機械検査しない。

| # | 内容 |
|---|---|
| 5-1 | `docs/rules/notation.md` が存在し、応答言語（AC-2）と mermaid（AC-3）の両方に言及すること — キーワードの存在までは検査しうる |
| 5-2 | CLAUDE.md が `@docs/rules/notation.md` を含み、README 一覧に行があること（AC-4）— 参照の存在は検査しうる。`docs/specs/issue-command.md` AC-8-a と同じく「参照が張られているか」までで、「本文が正しいか」は検査できない |
| 5-3 | **応答言語が日本語であることは機械検査しない。** 応答は振る舞いであり、CI に痕跡が残らない（`docs/harness/verification-loop.md`「artifact に残らないものは検査できない」と同型）。担保は Rules 層の明文化と、それを読むエージェントの遵守に留まる |
| 5-4 | **新規 docs の図が mermaid であることは機械検査しない。** 既存 ASCII との混在を許すため（非スコープ）、「新規かどうか」を機械が判定できない。これは仕様どおりの限界であって欠陥ではない |

**「表記ルールを明文化したので応答が日本語になる」と読める AC を後から足さないこと。** 明文化が保証するのは規約の存在だけであり、遵守そのものではない（AC-9 系の限界を他仕様と同様に固定する）。
