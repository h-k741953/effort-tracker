MVP ユースケース1「**稼働実績の入力・編集**」の受け入れ条件。根拠は Issue #5 の議論と `docs/domain/ubiquitous-language.md`。

**確定済みのユビキタス言語・丸め規則・状態遷移はこの仕様へ書き写さない。** 正解は `docs/domain/ubiquitous-language.md` にあり、本仕様はそれを参照して「入力・編集が満たすべき形」だけを定める（ADR 0004）。

- **決定者**: 人間（プロジェクトオーナー）。業務ルールは `docs/ai-collaboration.md` の責務分界に従い人間が決定した（Issue #5 で選択）
- **日付**: 2026-07-23（**2026-07-28 に D-9・AC-5-5 を追記**。Issue #51 で人間が明示選択して確定した業務ルールであり、決定者は同じく人間）
- **改定**: **2026-10-09 に入力方式を改定した**（D-2・D-3 を置き換え、D-10 を追加し、AC-2-1・AC-3・AC-6 を改めた）。決定者は人間（テーマ B の画面デザイン刷新に際しての決定。オーケストレーター経由で受領）。改定で生じた論点（旧 U-1〜U-6）は、2026-10-10 に人間が決定し、D-11〜D-16 として**決定表へ移した**ものである（同じくオーケストレーター経由で受領）。同じく 2026-10-10 に人間が、D-7 の字面を受け付ける入力から実際に生じる範囲へ改めること（D-7）と、時刻を稼働実績に保存すること（D-17）を決定した

## スコープ

**MVP ユースケース1（稼働実績の入力・編集）のみ**を対象とする。

- 対象: 勤務月（`WorkMonth`）の生成、稼働実績（`DailyRecord`）の入力・編集・削除、時刻からの稼働時間の算出、総稼働時間（`TotalHours`）の算出
- 非対象: **月次締め（Issue #6）・承認申請/承認（Issue #7）**。締め条件・状態遷移の操作はそれぞれの仕様が持つ。本仕様は「下書き状態での入力・編集」に閉じる
- 非対象: 契約の管理（与件として扱う。`docs/rules/scope.md`）、技術者の横断ビュー、請求・支払・ファイル添付

## 決定（人間が選択した業務ルール）

推測で埋めず、人間が明示選択した。D-1〜D-9 は Issue #5 / #51、D-2・D-3 の改定と D-10 は 2026-10-09、D-7 の字面の改定と D-11〜D-17 は 2026-10-10 の決定である。**各行の決定者は人間である。**

| # | 論点 | 決定 |
|---|---|---|
| D-1 | 1日の稼働レコード数 | **1日1レコード**（`DailyRecord`＝「1日分の記録」の定義に整合） |
| D-2 | 入力形式 | **【2026-10-09 人間決定で改定】開始時刻・終了時刻・休憩から稼働時間を算出する。稼働時間そのものを直接入力しない。** 算出式は `稼働時間 ＝（終了時刻 − 開始時刻）−（休憩ありなら 休憩終了時刻 − 休憩開始時刻）`。**置き換えた旧決定**（Issue #5）: 「稼働時間そのものを直接入力する（開始・終了時刻から算出しない）」 |
| D-3 | 休憩 | **【2026-10-09 人間決定で改定】休憩の有無を選ぶ。休憩ありのときは休憩開始時刻・休憩終了時刻を入力し、その間を稼働時間から差し引く。** 休憩なしのときは休憩の時刻を持たない。休憩は**1日1回まで**とする（D-12）。**置き換えた旧決定**（Issue #5）: 「休憩時間は入力させない（稼働時間に含めない前提。D-2 の帰結）」 |
| D-4 | 未来日 | **当日まで許可。未来日は不可** |
| D-5 | 稼働ゼロの日と未入力の日 | **区別しない。** レコードのない日は「稼働なし」とみなす。総稼働時間はレコードのある日のみ合計する |
| D-6 | 勤務月の生成タイミング | **初回入力時に暗黙生成**する（明示的に「月を開く」操作は無い） |
| D-7 | 1日の稼働時間の下限と上限 | **【2026-10-10 人間決定で字面を改定】0時間15分 以上 23時間45分 以下**のみ許可。範囲外は弾く。深夜・休日区分は非スコープ。D-2 で算出した稼働時間に掛かる不変条件である。この範囲は D-10・D-11・D-13 の帰結と一致する。下限 0時間15分 は、15分刻み（D-10）で終了＞開始（D-16）とし、稼働 0 を弾く（D-13）ことから生じる最小である。上限 23時間45分 は、`0:00`〜`23:45`（D-11）から生じる最大である（AC-3-12）。**置き換えた旧字面**（Issue #5）: 「0時間0分 以上 24時間0分 以下」。旧字面の下限と上限は、2026-10-09 の改定後はいずれも受け付ける入力から到達しない値になっていた |
| D-8 | 「当日」の基準タイムゾーン | **JST（`Asia/Tokyo`）**。未来日判定（D-4）の境界日はこの基準で決める |
| D-9 | 当該勤務月の年月に属さない対象日への**削除** | **弾く。** 入力（AC-2-4）と同じ扱いにする。勤務月は当該年月の稼働実績だけを保持する（P-1・AC-2-4「他の月の日を混在させない」）ため、その年月に属さない日は削除の対象にもならない。**D-5「レコードのない日への削除は成功」は当該年月に属する対象日についての規則であり、属さない対象日には及ばない**（Issue #51、2026-07-28 に人間が確定） |
| D-10 | 時刻の粒度と値域 | **【2026-10-09 人間決定】各時刻（開始・終了・休憩開始・休憩終了）は時と分を選んで指定する。分は 0・15・30・45 の4値（15分刻み）。時は 0〜23。** 時 24 は選べない（`24:00` を含む。D-11）。したがって各時刻の値域は `0:00` 以上 `23:45` 以下である |
| D-11 | 日跨ぎと 24:00 | 2026-10-10 人間決定。**日跨ぎも `24:00` も許さない** とする。1日の勤務は対象日の中で完結し、終了時刻の最大は `23:45` である。終了時刻が開始時刻より前の入力を、終了が翌日の勤務として読まない（AC-3-5-b・3-5-c）。退けた案: `24:00` だけを終了に許す案、日跨ぎ（終了＜開始を翌日と読む）を許す案 |
| D-12 | 休憩の回数 | 2026-10-10 人間決定。**休憩は1日1回のみ**とする。稼働実績が持つ休憩は0個または1個である（AC-3-10）。退けた案: 複数回の休憩を許す案 |
| D-13 | 稼働時間が 0 になる入力 | 2026-10-10 人間決定。休憩が勤務時間全体と一致し、算出した稼働時間が 0時間0分 になる入力を**受け付けず弾く**ものとする（AC-3-9）。稼働の無い日はレコードを作らないことで表す。これは D-5（稼働ゼロの日と未入力の日を区別しない）と整合する。退けた案: 0時間0分 を値として受け付ける案 |
| D-14 | 丸め規則の扱い | 2026-10-10 人間決定。日ごとの15分切り捨て（P-3、ユビキタス言語「丸め規則」【確定】）を**変えずに残す**ものとする。時刻から算出した値は常に15分の倍数であり、切り捨てで値は変わらない（AC-6-2-a）。退けた案: 15分刻みが入力で担保されるとして規則を廃する案 |
| D-15 | 改定前の稼働実績 | 2026-10-10 人間決定。稼働時間だけを持ち時刻を持たない改定前のレコードは**移行せず破棄**し、新形式（D-2・D-3 の時刻を持つ形）だけにする。デモデータは日次リセットされる（`docs/rules/cost-guardrails.md` の表「デモデータ」）ため、旧形式を読み続ける必要が無い（AC-2-5）。退けた案: 旧形式のまま読めるようにする案、機械的に時刻へ変換する案 |
| D-16 | 時刻の前後関係と休憩の位置 | 2026-10-10 人間決定。AC-3 の 3-B の条文どおりに確定する。終了時刻＞開始時刻、休憩終了時刻＞休憩開始時刻とし、**いずれも厳密な不等号**で判定する。休憩は勤務時間の中に収め、勤務時間の**端点を含む**ものとする。すなわち休憩開始時刻＝開始時刻、休憩終了時刻＝終了時刻を許す。退けた案: 端点を含めない案 |
| D-17 | 時刻の保存 | 2026-10-10 人間決定。稼働実績は、入力された**開始時刻・終了時刻・休憩の有無**と、休憩ありのときの**休憩開始時刻・休憩終了時刻**を保存する。稼働時間は保存した時刻から算出する（D-2）。算出値を時刻と別に保存するかは永続化の詳細であり、実装工程が決める（AC-7-3）。別に保存する場合も、保存した時刻からの算出値と食い違わせない（AC-2-1・AC-2-6） |

### AC-2. 稼働実績の入力（1日1レコード）

| # | 条件 | 期待 |

| 2-2 | 同一勤務月内の対象日 | **一意（1日最大1レコード）**（D-1） |
| 2-3 | 既にレコードのある日への入力 | 新規作成ではなく、その日のレコードの**編集**として扱う（AC-5） |

| 2-5 | 時刻を持たない稼働実績（改定前の形式。稼働時間だけを持つもの） | **受け付けず保持もしない**ものとする（D-15）。開始時刻・終了時刻を欠く入力は 3-3 で弾く。改定前に保持していたレコードは移行せず破棄する。破棄の手段（永続化の列の扱い・デモデータの投入）は実装工程が `docs/specs/workmonth-implementation-design.md` 側で定める |

### AC-3. 時刻の検証と稼働時間の算出

本 AC は 2026-10-09 の改定で**全面的に置き換えた**ものである。旧 AC-3（稼働時間そのものの値域。3-1 `0時間0分` を許可／3-2 `24時間0分` を許可／3-3 `24時間1分` を弾く／3-4 負を弾く／3-5 分が 0〜59 外を弾く）は、稼働時間を直接受け取らなくなったため（D-2）入力の検証としては廃した。1日の稼働時間の下限・上限は、D-7 として算出値に掛かる**不変条件に残る**ものとする（3-12）。

**検証の出所**: 3-1・3-2（粒度と値域）は D-10・D-11、3-3・3-4（必須の時刻）は D-2・D-3 による。3-5〜3-10（前後関係・休憩の位置・休憩の回数・稼働 0）は、仕様工程がハンドオフ（`design/handoff/2026-10-theme-b/README.md` §5 の検証メッセージ。記録であって正ではない）を参考に起こした条文を、**2026-10-10 に人間が確定した**ものである（D-11・D-12・D-13・D-16）。本 AC の行はいずれも人間決定に基づき、期待が定まっている。

時刻の表記は `時:分`（例 `9:00`）。各行は**その行の条件だけに違反し、他の条件をすべて満たす**入力で読む。

#### 3-A. 時刻の粒度と値域（D-10・D-11）

| # | 入力 | 期待 |
|---|---|---|
| 3-1 | 分が 0・15・30・45 のいずれか（例: 開始 `9:00` / `9:15` / `9:30` / `9:45`） | 許可 |
| 3-1-a | 分がそれ以外（例: `9:10`・`9:14`・`9:16`・`9:59`・`9:60`・分が負） | **弾く**（4つの時刻のいずれに現れても同じ） |
| 3-2 | 時が 0〜23（例: 開始 `0:00`、終了 `23:45`） | 許可。`0:00` は各時刻の最小、`23:45` は最大 |
| 3-2-a | 時が負、または 25 以上 | **弾く** |
| 3-2-b | 時が 24（例: 終了 `24:00`、開始 `24:00`、休憩終了 `24:00`） | D-11 により**弾く**ものとする。`24:00` を含め、時 24 は4つの時刻のいずれに現れても弾く。`0:00`〜`23:45` は許可し（3-2）、`0:00`〜`24:00` は弾く |
| 3-3 | 開始時刻または終了時刻が未指定 | **弾く** |
| 3-4 | 休憩ありで、休憩開始時刻または休憩終了時刻が未指定 | **弾く** |
| 3-4-a | 休憩なし | 休憩の時刻を求めない（未指定で許可する） |

#### 3-B. 時刻の前後関係と休憩の位置（D-11・D-12・D-13・D-16）

| # | 入力（開始〜終了／休憩） | 期待 |
|---|---|---|
| 3-5 | `9:00`〜`9:15`／休憩なし | 許可。稼働時間 0時間15分（終了が開始より後の最小） |
| 3-5-a | `9:00`〜`9:00`（終了＝開始） | **弾く** |
| 3-5-b | `18:00`〜`9:00`（終了が開始より前） | D-11 により**弾く**ものとし、日跨ぎ（終了が翌日）として読まない |
| 3-5-c | `22:00`〜`2:00`（終了が翌日にあたる勤務） | D-11 により**弾く**ものとし、終了を翌日の `2:00` と読まない |
| 3-5-d | `23:30`〜`23:45`／休憩なし | 許可。稼働時間 0時間15分（開始として選べる最大の時刻での最小の勤務） |
| 3-5-e | 開始 `23:45`（例: `23:45`〜`23:45`、`23:45`〜`0:00`） | 開始 `23:45` を含む入力は**いずれも弾く**ものとする。終了の最大が `23:45`（D-11）であり、終了＞開始（D-16）を満たす終了時刻が存在しないためである |
| 3-6 | `9:00`〜`18:00`／休憩 `12:00`〜`12:15` | 許可。稼働時間 8時間45分（休憩終了が休憩開始より後の最小） |
| 3-6-a | `9:00`〜`18:00`／休憩 `12:00`〜`12:00`（休憩終了＝休憩開始） | **弾く** |

#### 3-C. 算出（D-2・D-7）

| 3-12 | 算出した稼働時間 | D-7（0時間15分 以上 23時間45分 以下）を**常に満たす**ものとする。3-A・3-B を満たす入力では、算出値はこの範囲に収まり、範囲の両端に到達する。最小の 0時間15分 は 3-5・3-5-d・3-9-b、最大の 23時間45分 は 3-11-c。範囲の外側の 0時間0分 は 3-9 で弾き（D-13）、24時間0分 は時 24 を弾く（3-2-b・D-11）ため生じない |

### AC-5. 編集・削除と、状態による可否

| # | 勤務月の状態 | 操作 | 期待 |
|---|---|---|---|
| 5-1 | 下書き（`Draft`） | 稼働実績の入力・編集・削除 | 許可 |
| 5-2 | 締め済（`PendingApproval`） | 入力・編集・削除 | **弾く**（P-5） |
| 5-3 | 承認済（`Approved`） | 入力・編集・削除 | **弾く**（P-5） |
| 5-4 | 下書き | **当該勤務月の年月に属する**ある日のレコードを削除する | そのレコードを取り除く。以降その日は「レコードのない日＝稼働なし」として扱う（D-5）。**明示的なゼロ記録を残す必要はない。** 当該日にレコードが無くても成功として扱う（D-5） |
| 5-5 | 下書き | **当該勤務月の年月に属さない**対象日（例: `2026-07` の勤務月に対する `2026-08-01` や `2026-06-30`）のレコードを削除する | **弾く**（D-9）。**当該日にレコードがあるか否かを問わず、勤務月が生成済みか否かも問わず弾く。** 5-4 の「レコードのない日への削除は成功」を適用しない |

### AC-6. 総稼働時間の算出

| # | 条件 | 期待 |
|---|---|---|
| 6-1 | 総稼働時間 | **各日の稼働時間（AC-2-1-a で算出した値）を15分単位で切り捨て、レコードのある日を合計**する（P-3）。合計してから丸めない |
| 6-2 | 例（丸め規則そのもの） | ある日が 8時間50分 なら、その日の寄与は 8時間45分（P-3 の例と同じ）。2026-10-09 の改定後、時刻からの算出（D-10 の15分刻み）では 8時間50分 のような値は**生じない**ものとなった。改定前の時刻を持たない稼働実績も移行しない（D-15）ため、**入力を経由してこの例を再現する手段は無い**。本行は丸め規則（D-14 で残すと決定）そのものの例として残す。規則そのものの検証をどの単位のテストで行うかはテスト工程が決める |
| 6-2-a | 時刻から算出した値の寄与 | 算出値は常に15分の倍数であるため、切り捨てで**値は変わらない**ものとなる。例: `9:00`〜`18:00`／休憩 `12:00`〜`13:00` → 8時間0分 → 寄与 8時間0分。`9:15`〜`17:45`／休憩 `12:30`〜`13:15` → 7時間45分 → 寄与 7時間45分。丸め規則は D-14 により残し、P-3 のとおり適用する |
| 6-3 | レコードのない日 | 合計に寄与しない（0として数えない＝そもそも項に現れない。D-5） |
| 6-4 | 総稼働時間と精算幅の比較（超過・不足の算出）、締め可否の判定 | **本仕様の対象外。** Issue #6（月次締め）が持つ |

### AC-7. 限界 — 本仕様が担保しないこと

**以下は仕様どおりであり、欠陥ではない。**

| # | 内容 |
|---|---|
| 7-1 | **締めの完全性を問わない**（D-5 の帰結）。ゼロ日と未入力を区別しないため、「全日入力済み」を締め条件にできない。締められる条件は Issue #6 が別途定める。本仕様は「入力されたものだけを保持・合計する」ことに閉じる |
| 7-2 | **超過・締め・承認は対象外**（AC-6-4）。本仕様は UC1（入力・編集）に閉じ、UC2（#6）・UC3（#7）へ渡す |
| 7-3 | 本仕様は受け入れ条件のみを定め、内部レイヤー配置（clean architecture の各リング）や永続化の詳細は実装工程が `docs/adr/0008` に従って決める |
| 7-4 | **2026-10-09 の改定と 2026-10-10 の決定（D-7 の字面・D-11〜D-17）は、本仕様を参照する他の仕様へまだ波及していない。** `docs/specs/domain-api-http-contract.md`（リクエストボディ・レスポンスの時刻・値域外のエラー・未知フィールドの注記・2つ目の休憩に当たる値の扱い）、`docs/specs/workmonth-implementation-design.md`（`WorkingHours` / `DailyRecord` の値域検査の置き場所、時刻を保存する永続化の列、旧形式のレコードの破棄）、`docs/specs/daily-record-entry-ui.md`（入力項目・入力手段）、`docs/specs/design-system.md`（`NumberField` の導出元）は旧 D-2・D-3・旧 AC-3 を前提にしている。**これらは本仕様の条文と食い違っており、改めるまでは本仕様が正とする**（ADR 0004）。改定はそれぞれの工程が行う |
| 7-5 | 深夜・休日の区分、残業の区分、祝日による扱いの違いは持たない（D-7）。時刻を持つようになっても、時間帯で稼働時間を区分しない。画面のカレンダーが祝日を表示しても（`docs/adr/0021-mvp-scope-expansion-and-self-hosted-fonts.md`）、それは表示に限られ、本仕様の検証・算出のいずれにも影響しない |
