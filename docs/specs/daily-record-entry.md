# 稼働実績の入力・編集 — 仕様

MVP ユースケース1「**稼働実績の入力・編集**」の受け入れ条件。根拠は Issue #5 の議論と `docs/domain/ubiquitous-language.md`。

**確定済みのユビキタス言語・丸め規則・状態遷移はこの仕様へ書き写さない。** 正解は `docs/domain/ubiquitous-language.md` にあり、本仕様はそれを参照して「入力・編集が満たすべき形」だけを定める（ADR 0004）。

- **決定者**: 人間（プロジェクトオーナー）。業務ルールは `docs/ai-collaboration.md` の責務分界に従い人間が決定した（Issue #5 で選択）
- **日付**: 2026-07-23（**2026-07-28 に D-9・AC-5-5 を追記**。Issue #51 で人間が明示選択して確定した業務ルールであり、決定者は同じく人間）

---

## スコープ

**MVP ユースケース1（稼働実績の入力・編集）のみ**を対象とする。

- 対象: 勤務月（`WorkMonth`）の生成、稼働実績（`DailyRecord`）の入力・編集・削除、総稼働時間（`TotalHours`）の算出
- 非対象: **月次締め（Issue #6）・承認申請/承認（Issue #7）**。締め条件・状態遷移の操作はそれぞれの仕様が持つ。本仕様は「下書き状態での入力・編集」に閉じる
- 非対象: 契約の管理（与件として扱う。`docs/rules/scope.md`）、技術者の横断ビュー、請求・支払・ファイル添付

---

## 前提（P）— 確定事項（参照のみ、再定義しない）

`docs/domain/ubiquitous-language.md` の確定事項を前提とする。本仕様はこれらを覆さない。

| # | 前提 | 出典 |
|---|---|---|
| P-1 | 勤務月は `契約 × 年月` で一意。集約ルートは `WorkMonth` の1つのみ | ユビキタス言語「勤務月の同一性」 |
| P-2 | 勤務月の生成時に、契約から精算幅（`SettlementRange`）を値オブジェクトとして複写する | ユビキタス言語「契約と精算幅の保持」 |
| P-3 | 総稼働時間は、日次の各実績を**15分単位で切り捨て**てから合計する（合計してから丸めない） | ユビキタス言語「丸め規則」 |
| P-4 | 稼働実績（`DailyRecord`）は勤務月に属し、単独では存在しない | ユビキタス言語「稼働の記録」 |
| P-5 | 下書き（`Draft`）状態でのみ技術者が編集できる。締め済（`PendingApproval`）・承認済（`Approved`）は編集不可 | ユビキタス言語「状態と操作」 |

## 決定（Issue #5 で人間が選択した業務ルール）

推測で埋めず、Issue #5 で人間が明示選択した。**各行の決定者は人間である。**

| # | 論点 | 決定 |
|---|---|---|
| D-1 | 1日の稼働レコード数 | **1日1レコード**（`DailyRecord`＝「1日分の記録」の定義に整合） |
| D-2 | 入力形式 | **稼働時間そのものを直接入力**する（開始・終了時刻から算出しない） |
| D-3 | 休憩時間 | **入力させない**（稼働時間に含めない前提。D-2 の帰結） |
| D-4 | 未来日 | **当日まで許可。未来日は不可** |
| D-5 | 稼働ゼロの日と未入力の日 | **区別しない。** レコードのない日は「稼働なし」とみなす。総稼働時間はレコードのある日のみ合計する |
| D-6 | 勤務月の生成タイミング | **初回入力時に暗黙生成**する（明示的に「月を開く」操作は無い） |
| D-7 | 1日の稼働時間の上限 | **0時間0分 以上 24時間0分 以下**のみ許可。範囲外は弾く。深夜・休日区分は非スコープ |
| D-8 | 「当日」の基準タイムゾーン | **JST（`Asia/Tokyo`）**。未来日判定（D-4）の境界日はこの基準で決める |
| D-9 | 当該勤務月の年月に属さない対象日への**削除** | **弾く。** 入力（AC-2-4）と同じ扱いにする。勤務月は当該年月の稼働実績だけを保持する（P-1・AC-2-4「他の月の日を混在させない」）ため、その年月に属さない日は削除の対象にもならない。**D-5「レコードのない日への削除は成功」は当該年月に属する対象日についての規則であり、属さない対象日には及ばない**（Issue #51、2026-07-28 に人間が確定） |

## 受け入れ条件（AC）

| AC | 主題 | 主に効く工程 |
|---|---|---|
| AC-1 | 初回入力時の勤務月の暗黙生成（D-6・P-2） | tester・implementer |
| AC-2 | 稼働実績の入力（1日1レコード・D-1/D-2） | tester・implementer |
| AC-3 | 稼働時間の値域バリデーション（D-7） | tester・implementer |
| AC-4 | 未来日の制限（D-4） | tester・implementer |
| AC-5 | 編集・削除と、状態による可否（P-5・D-5・D-9） | tester・implementer |
| AC-6 | 総稼働時間の算出（P-3・D-5） | tester・implementer |
| AC-7 | 限界 — 本仕様が担保しないこと | reviewer |

### AC-1. 勤務月の暗黙生成

| # | 条件 | 期待 |
|---|---|---|
| 1-1 | ある契約・年月に対応する勤務月が**無い**状態で、その年月に属する日の稼働実績を入力する | 当該 `契約 × 年月` の勤務月を新規生成し、そこへ実績を追加する |
| 1-2 | 勤務月の生成時 | 契約から精算幅を値オブジェクトとして複写する（P-2）。以降、契約の変更は当該勤務月に遡及しない |
| 1-3 | 生成された勤務月の初期状態 | **下書き（`Draft`）** |
| 1-4 | 既に勤務月が存在する年月への入力 | 新規生成せず、既存の勤務月へ追加する |
| 1-5 | 「月を開く」等の明示操作 | **存在しない。** 入力以外の生成契機を設けない（D-6） |

### AC-2. 稼働実績の入力（1日1レコード）

| # | 条件 | 期待 |
|---|---|---|
| 2-1 | 稼働実績は **対象日** と **稼働時間** を持つ | 稼働時間は時・分で直接指定する（D-2）。開始・終了時刻や休憩時間は持たない（D-3） |
| 2-2 | 同一勤務月内の対象日 | **一意（1日最大1レコード）**（D-1） |
| 2-3 | 既にレコードのある日への入力 | 新規作成ではなく、その日のレコードの**編集**として扱う（AC-5） |
| 2-4 | 対象日が当該勤務月の年月に属さない | 弾く（勤務月は `契約 × 年月`。他の月の日を混在させない） |

### AC-3. 稼働時間の値域バリデーション

| # | 入力（1日の稼働時間） | 期待 |
|---|---|---|
| 3-1 | 0時間0分 | 許可（ゼロを値として受ける。ただし D-5 によりゼロ記録に特別な意味は持たせない） |
| 3-2 | 24時間0分 | 許可（上限は含む） |
| 3-3 | 24時間を超える（例: 24時間1分） | **弾く**（D-7） |
| 3-4 | 負の値 | 弾く |
| 3-5 | 分が 0〜59 の範囲外 | 弾く |

### AC-4. 未来日の制限

| # | 対象日 | 期待 |
|---|---|---|
| 4-1 | 当日 | 許可 |
| 4-2 | 当日より過去 | 許可 |
| 4-3 | 当日より後（未来日） | **弾く**（D-4） |

> **「当日」は JST（`Asia/Tokyo`）で判定する**（D-8）。境界（当日の 23:59 と翌日の 00:00）はこの基準で決める。

### AC-5. 編集・削除と、状態による可否

| # | 勤務月の状態 | 操作 | 期待 |
|---|---|---|---|
| 5-1 | 下書き（`Draft`） | 稼働実績の入力・編集・削除 | 許可 |
| 5-2 | 締め済（`PendingApproval`） | 入力・編集・削除 | **弾く**（P-5） |
| 5-3 | 承認済（`Approved`） | 入力・編集・削除 | **弾く**（P-5） |
| 5-4 | 下書き | **当該勤務月の年月に属する**ある日のレコードを削除する | そのレコードを取り除く。以降その日は「レコードのない日＝稼働なし」として扱う（D-5）。**明示的なゼロ記録を残す必要はない。** 当該日にレコードが無くても成功として扱う（D-5） |
| 5-5 | 下書き | **当該勤務月の年月に属さない**対象日（例: `2026-07` の勤務月に対する `2026-08-01` や `2026-06-30`）のレコードを削除する | **弾く**（D-9）。**当該日にレコードがあるか否かを問わず、勤務月が生成済みか否かも問わず弾く。** 5-4 の「レコードのない日への削除は成功」を適用しない |

> **5-5 は業務検証である。** 状態（5-2・5-3）や操作者の認可より後に判定される。複数の条件に同時に該当したときにどれを返すか（判定順序）の正解は `docs/specs/domain-api-http-contract.md` AC-9 が持ち、本仕様には書き写さない。HTTP 上の表現も同 AC-5-8 が持つ。

### AC-6. 総稼働時間の算出

| # | 条件 | 期待 |
|---|---|---|
| 6-1 | 総稼働時間 | **各日の稼働時間を15分単位で切り捨て、レコードのある日を合計**する（P-3）。合計してから丸めない |
| 6-2 | 例 | ある日が 8時間50分 なら、その日の寄与は 8時間45分（P-3 の例と同じ） |
| 6-3 | レコードのない日 | 合計に寄与しない（0として数えない＝そもそも項に現れない。D-5） |
| 6-4 | 総稼働時間と精算幅の比較（超過・不足の算出）、締め可否の判定 | **本仕様の対象外。** Issue #6（月次締め）が持つ |

### AC-7. 限界 — 本仕様が担保しないこと

**以下は仕様どおりであり、欠陥ではない。**

| # | 内容 |
|---|---|
| 7-1 | **締めの完全性を問わない**（D-5 の帰結）。ゼロ日と未入力を区別しないため、「全日入力済み」を締め条件にできない。締められる条件は Issue #6 が別途定める。本仕様は「入力されたものだけを保持・合計する」ことに閉じる |
| 7-2 | **超過・締め・承認は対象外**（AC-6-4）。本仕様は UC1（入力・編集）に閉じ、UC2（#6）・UC3（#7）へ渡す |
| 7-3 | 本仕様は受け入れ条件のみを定め、内部レイヤー配置（clean architecture の各リング）や永続化の詳細は実装工程が `docs/adr/0008` に従って決める |
