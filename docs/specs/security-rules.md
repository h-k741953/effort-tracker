# セキュリティ規約 — ランタイム認証を ADR 0013 / 0014 基準へ同期する

Issue #57 の仕様。`docs/rules/security.md` のランタイム認証の記述が**廃止済みの ADR 0005（Vercel → AWS の OIDC Federation）を参照したまま**であり、ADR 0013 / 0014 と矛盾している。この規約本文を最新の決定へ同期するための**受け入れ条件**を定める。

**新たな技術選定ではなく、決定済み事項の規約への同期である。したがって ADR は起こさない。** 決定の本文（なぜ実行ロールなのか・なぜ Vercel を離れたのか）はこの仕様へ書き写さない。正解は `docs/adr/0014-execution-role-over-vercel-oidc.md` および `docs/adr/0013-aws-native-hosting-over-vercel.md` にあり、本仕様はそれを参照して「規約本文が満たすべき形」だけを定める（ADR 0004）。

---

## スコープ

**`docs/rules/security.md` の記述を ADR 0013 / 0014 基準へ更新すること**、および `docs/rules/` 配下に廃止 ADR 0005 / Vercel への参照が残らないことを対象とする。

対象は既存の4項目のうち、AWS 認証に関する箇条（現行 L6-L9）に限る。`.gitignore` / シークレット非記載 / gitleaks の3項目（現行 L3-L5）は本仕様の対象外であり、書き換えない。

### 非スコープ

- **ADR の新規作成・変更。** 本件は決定済み事項の同期であり、ADR を要する判断を含まない（この点は人間が確認済み）
- **CI → AWS の GitHub OIDC を ADR 化すること。** 根拠 ADR が存在しない事実は P-3 に固定し、本仕様では解消しない
- **ADR 0005 / 0002 の本文を書き換えること。** 廃止 ADR は本文を書き換えず追記もしない（ADR 0001 運用ルール3）
- **Terraform の実装**（信頼ポリシー・実行ロール・OIDC プロバイダの削除。Issue #8）と、**Cognito の実装**（Issue #52）。本仕様は規約本文のみを対象とする
- **README.md の更新。** README にも廃止 ADR 0005 / Vercel OIDC Federation を前提とした記述が残る（技術スタック表・「セキュリティ」節の計3箇所・実測）。本仕様の対象は `docs/rules/` であり、README の同期は**別 Issue として人間の判断を仰ぐ**（AC-5-4 に残留として固定する）
- **実行ロールの権限最小化（`lambda:InvokeFunctionUrl` を当該関数のみ）を規約本文へ明文化すること。** ADR 0014 決定に記載があり、規約へ写すか否かは判断が要る（AC-1-6 の注記）
- **`sub` 条件を `repo:[OWNER]/[REPO]` より細かい粒度（`ref:` / `environment:` 等）まで固定すること。** 粒度の決定は Terraform 実装（Issue #8）の範囲であり、本仕様は下限のみを定める（AC-4-4）

## 前提（P）

### P-1. 決定は ADR 0013 / 0014 で確定済み

本仕様は新たな技術選定・業務ルールを決めない。ADR 0014 が確定させた「Vercel OIDC Federation を廃止し、BFF Lambda は自身の実行ロールで SigV4 署名してドメイン API を呼ぶ」を、Rules 層（`docs/rules/`）で読める形へ同期するだけである。したがって本仕様の AC は「どう決めるか」ではなく「規約本文が決定を正しく写しているか」だけを問う。

### P-2. 廃止 ADR は規約から参照しない

ADR 0005 のステータスは「廃止（0014 により置換）」である。`docs/` が持つのは**決定した最新のもののみ**であり（ADR 0004）、規約本文が廃止 ADR を根拠として指している状態は、古い仕様を正しく実装させる経路になる。ADR 0005 のファイル自体は残す（書き換えない）が、**規約からの参照は落とす**。

### P-3. CI → AWS の GitHub OIDC には根拠 ADR が無い

`docs/` 全体で「GitHub OIDC」の語は `docs/rules/security.md` にしか現れず、CI → AWS の認証方式を決めた ADR は存在しない（実測）。**ランタイム側は ADR 0014 に根拠があるが、CI 側は規約本文が唯一の記述である**という非対称がある。

本仕様はこの非対称を**解消せず、現状のまま維持する**。理由は、解消には ADR を起こす判断（＝人間の承認事項）が要り、それは「決定済み事項の同期」という本件の性質を超えるためである。規約本文には**存在しない ADR 番号を参照させない**（AC-2-3）。

### P-4. 検査対象のインフラは未実装

`.github/workflows/` に AWS 認証のステップは存在せず（`aws-actions` / `role-to-assume` の記述なし・実測）、`infra/terraform` は未着手である（`docs/harness/verification-loop.md`）。`apps/web` はスキャフォールド済みだが、SigV4 署名の実体である **`apps/web/src/lib/lambda-client.ts` は未実装**である（`docs/specs/web-app-scaffold.md` の非スコープ。呼び先のドメイン API Lambda が存在してから作る）。**規約本文は「これから作るものへの制約」であり、本仕様の時点で機械検査できる対象は文書だけである。** この帰結は AC-7 に限界として固定する。

## 受け入れ条件（AC）

| AC | 主題 | 主に効く工程 |
|---|---|---|
| AC-1 | ランタイム認証の記述を ADR 0014 基準へ置き換える | implementer・reviewer |
| AC-2 | CI → AWS の GitHub OIDC を維持し、根拠の所在を偽らない | implementer・reviewer |
| AC-3 | 静的キー禁止の不変条件を AWS ネイティブ前提で保つ | implementer・reviewer |
| AC-4 | `sub` 条件必須の不変条件を保ち、脅威モデルだけを言い換える | implementer・reviewer |
| AC-5 | 廃止 ADR 0005 / Vercel への参照を `docs/rules/` に残さない | tester・reviewer |
| AC-6 | サービス間認証とエンドユーザー認証のレイヤーを取り違えない | implementer・reviewer |
| AC-7 | 機械検査できる範囲と、できない限界を固定する | tester・reviewer |

### AC-1. ランタイム認証の記述（ADR 0014 基準）

現行 L8「ランタイム（Vercel）→ AWS: Vercel OIDC Federation（`docs/adr/0005`）」を置き換える。置換後の記述は次を満たす。

| # | 内容 |
|---|---|
| 1-1 | 主体を **AWS 上で動く BFF / SSR Lambda**（Next.js サーバー）と書く。「Vercel」を主体としない |
| 1-2 | 呼び先を**ドメイン API の Lambda Function URL** と書く |
| 1-3 | 認証手段を **BFF Lambda 自身の実行ロールによる SigV4 署名**と書く。federation を介さないことが読み取れること |
| 1-4 | 参照先 ADR を **`docs/adr/0014`**（必要なら前提として `docs/adr/0013`）とする。**`docs/adr/0005` を参照しない**（P-2） |
| 1-5 | **Vercel OIDC Federation を作らない**旨を明記する。具体的には AWS 側の OIDC ID プロバイダ（`oidc.vercel.com`）・Vercel 向け信頼ポリシー・Vercel の環境変数（`AWS_ROLE_ARN` 等）を作らない、と読み取れること |
| 1-6 | ADR 0014 の**決定の理由を書き写さない**。規約本文には守るべき制約だけを置く（ADR 0004） |

- Function URL の `authorization_type = "AWS_IAM"` は **`docs/rules/cost-guardrails.md` に既存の記述があるため、`security.md` へ設定値を書き写さない**（二重管理を作らない）。ADR 0003 / 0014 が維持されている前提として、参照に留めてよい
- 実行ロールの権限最小化（`lambda:InvokeFunctionUrl` を当該関数のみ）は**本仕様では規約本文へ足さない**（非スコープ）。足す判断が必要なら人間へ上げる

### AC-2. CI → AWS の GitHub OIDC（維持）

| # | 内容 |
|---|---|
| 2-1 | 現行 L7「CI（GitHub Actions）→ AWS: GitHub OIDC」に相当する記述を**残す**。削除・弱化しない |
| 2-2 | GitHub OIDC の記述から、廃止 ADR 0005 への参照が（直接・間接を問わず）効かないようにする。現行は L8 の `docs/adr/0005` が同一ブロック内にあり、CI 側の根拠と読めうる |
| 2-3 | **存在しない ADR 番号を参照しない。** CI → AWS の GitHub OIDC を決めた ADR は無い（P-3）。「ADR 00XX」の類を新たに書かない |
| 2-4 | 規約本文に「この項目には根拠 ADR が無い」というメタ情報を書かない。規約本文は規約だけを持つ（ADR 0004）。非対称の事実は本仕様 P-3 が保持する |

### AC-3. 静的キー禁止（不変条件・弱めない）

| # | 内容 |
|---|---|
| 3-1 | **「静的アクセスキーをどこにも置かない」を保つ。** 対象・強度を弱める書き換えをしない |
| 3-2 | 置き場所の例示から **Vercel の環境変数を外す**。AWS ネイティブ前提の置き場所（GitHub Secrets、Lambda の環境変数、Terraform 変数ファイル等）へ更新する |
| 3-3 | **例示は列挙であって限定ではない**と読めること。「例示に挙がっていない場所なら置いてよい」と解釈できる書き方をしない（3-1 の実効を例示で狭めない） |
| 3-4 | 上位命題の見出しを事実と合わせる。**現行の「AWS 認証は CI・ランタイムとも OIDC」は成立しなくなる**（ランタイムは OIDC ではなく実行ロール）。「長期認証情報を使わない（CI は GitHub OIDC、ランタイムは実行ロール）」の形へ改める。**「OIDC」を上位命題の名前に据えない** |

### AC-4. 信頼ポリシーの `sub` 条件（不変条件・脅威モデルのみ更新）

| # | 内容 |
|---|---|
| 4-1 | **「信頼ポリシーで `sub` 条件を省かない」を残す。** 削除しない。「`aud` だけで足りる」等、条件を緩められると読める記述を書かない |
| 4-2 | 適用対象を **GitHub OIDC の信頼ポリシー**と明示する。Vercel 向け信頼ポリシーは存在しなくなるため、対象が宙に浮かないようにする |
| 4-3 | 脅威モデルを言い換える。「Vercel にサインアップした任意の第三者が引き受けられる」→ **GitHub Actions の OIDC プロバイダは GitHub 利用者全体で共有されており、`sub` を省くと任意のリポジトリのワークフローが当該 IAM ロールを引き受けられる**、の趣旨へ改める。**これは脅威モデルの更新であって緩和ではない** |
| 4-4 | 固定粒度の**下限**として **`repo:[OWNER]/[REPO]` まで固定する**ことを書く。これより細かい粒度は本仕様で決めない（非スコープ）。値はダミー / プレースホルダで書く（`security.md` 既存の「例示は必ずダミー値」に従う） |

### AC-5. 残留参照ゼロ（`docs/rules/` 全体）

| # | 内容 |
|---|---|
| 5-1 | 変更後、**`docs/rules/` 配下に `Vercel` / `0005` / `oidc.vercel.com` の文字列が1つも残らない**こと。現状これらは `security.md` の L6 / L8 / L9 のみに存在する（他の rules ファイルには無い・実測） |
| 5-2 | 規約本文の実体は `docs/rules/security.md` のまま。**CLAUDE.md へコピーを作らない**（既存の `@docs/rules/security.md` の `@import` で参照される）。新規ファイルを作らないため `docs/rules/README.md` の一覧表は変更不要であり、**行を増やさない** |
| 5-3 | **ADR 本文（0002 / 0005 等）を書き換えない**（ADR 0001 運用ルール3）。`docs/specs/` 配下に Vercel / 0005 への参照は本仕様以外に無く（実測）、こちらも変更しない |

### AC-6. レイヤーの取り違え防止（Cognito との併存）

| # | 内容 |
|---|---|
| 6-1 | 本規約のランタイム認証の記述が**サービス間認証**（BFF → ドメイン API）を指すと読めること |
| 6-2 | エンドユーザー認証（Cognito・ADR 0016）を包含・置換すると読める記述を書かない。両者は**別レイヤーで併存**する（ADR 0016 決定） |
| 6-3 | Cognito 側の機密（Google OAuth のクライアントシークレット等）の扱いは、既存の「シークレットをコードやドキュメントに書かない」「`terraform.tfvars` は `.gitignore` 済み」で足りる。**本仕様で新たな記述を足さない**（Issue #52 の範囲） |

### AC-7. 機械検査の範囲と限界

**検査できるのは「規約本文に何が書かれているか」までである。** 規約が実際に守られているか（静的キーが本当にどこにも無いか・信頼ポリシーに `sub` 条件が実在するか）は、この仕様では機械検査しない。

| # | 内容 |
|---|---|
| 7-1 | `docs/rules/` 配下に `Vercel` / `0005` が現れないこと（AC-5-1）— **文字列検査は可能**。ただし検査そのものの新設は本仕様では要求しない。**検査範囲を `docs/rules/` より広げないこと。** リポジトリ全体へ広げると README・ADR 本文（いずれも意図的に据え置く。AC-5-3 / 5-4）に当たって落ちる |
| 7-2 | 静的キー禁止（AC-3-1）・`sub` 条件必須（AC-4-1）のキーワードが残存すること — **存在検査は可能**。ただし「不変条件が弱められていないか」は文意の問題であり、キーワードの存在では判定できない。担保はレビューに留まる |
| 7-3 | **静的アクセスキーがどこにも置かれていないことは機械検査しない。** `make scan-secrets`（gitleaks）が見るのは*このリポジトリにコミットされた*秘密であり、GitHub Secrets / Lambda 環境変数 / 外部サービスの設定に何が置かれているかは検査対象外である |
| 7-4 | **信頼ポリシーに `sub` 条件が実在することは機械検査しない。** `infra/terraform` が未着手で検査対象が存在しない（P-4）。将来 Terraform 側の検査で担保しうるが、**本仕様はそれを約束しない**。約束するなら Issue #8 の仕様で明示的に引き受ける |
| 7-5 | **BFF が実行ロールで SigV4 署名して呼ぶ実装になっていることは機械検査しない。** 署名の実体である `apps/web/src/lib/lambda-client.ts` が未実装であり（P-4）、検査対象が存在しない。**`apps/web` 自体はスキャフォールド済みだが、このファイルは `docs/specs/web-app-scaffold.md` の非スコープ**（呼び先のドメイン API Lambda が存在してから作る）であり、存在しないことは欠落ではない |
| 7-6 | **CI → AWS の GitHub OIDC が実際に設定されていることは機械検査しない。** 現時点で workflow に AWS 認証ステップ自体が無い（P-4）。規約は将来の実装への制約として先行する |

**「規約を ADR 0014 基準へ直したので、ランタイム認証が実際に実行ロールになる」と読める AC を後から足さないこと。** 同期が保証するのは規約本文の正しさだけであり、実装の遵守そのものではない（`docs/specs/notation-rules.md` AC-5 と同じ限界の置き方）。ここで検査できないものは、`docs/harness/verification-loop.md`「ハーネスの限界」と同じく人間の責務として残る。
