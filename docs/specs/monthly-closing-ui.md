# 月次締め — UI/画面 仕様

MVP ユースケース2「月次締め」の **UI/画面** 受け入れ条件。業務仕様は `docs/specs/monthly-closing.md` が持ち、本仕様はそれと矛盾しない範囲で「締め操作の画面が満たすべき形」だけを定める。画面骨格・状態×ロールの操作可否・read-only の共通挙動・超過／不足の表示タイミングは `docs/specs/work-month-screen-ui.md`（以下「共通仕様」）が持つ。

**業務ルール（締め可否・超過／不足の算出・状態遷移）はこの仕様へ書き写さない。** 正解は `docs/specs/monthly-closing.md` と `docs/domain/ubiquitous-language.md`。本仕様は参照のみ（ADR 0004）。

- **決定者**: 人間（プロジェクトオーナー）。UI 固有の未確定点は共通仕様「未確定点」に集約
- **日付**: 2026-07-23

---

## スコープ

- **対象**: 勤務月画面における**締め（`Close`）操作**の UI と、その状態（締め可能／締め不可／締め確認中／締め後 read-only）、締めの結果表示（状態バッジの遷移・超過／不足の表示）
- **非対象**: 承認・差戻しの UI（`approval-ui.md`）、稼働実績の入力・編集 UI（`daily-record-entry-ui.md`）、画面骨格・操作可否マトリクス（共通仕様）

---

## 前提（P）

| # | 前提 | 出典 |
|---|---|---|
| P-1 | 締めは `Draft` かつ技術者本人のみ提供（他の技術者・承認者には提供しない） | 共通仕様 AC-3／`monthly-closing.md` AC-1・AC-2 |
| P-2 | 締めは取り消せない。下書きへ戻す手段は承認者の差戻しのみ | `monthly-closing.md` D-4・AC-6 |
| P-3 | 超過／不足は締め時に算出・保存され、締め後に表示される | 共通仕様 AC-4／`monthly-closing.md` AC-3 |
| P-4 | 締めると状態は `PendingApproval` へ遷移し、稼働実績は read-only になる | 共通仕様 AC-5／`monthly-closing.md` AC-5 |

## 受け入れ条件（AC）

| AC | 主題 | 出典 |
|---|---|---|
| AC-1 | 締めボタンの提供条件 | 共通仕様 AC-3／`monthly-closing.md` AC-1・AC-2 |
| AC-2 | 締め確認ステップ | `monthly-closing.md` D-4・AC-6 |
| AC-3 | 締め後の帰結表示 | `monthly-closing.md` AC-3・AC-5 |
| AC-4 | 締め取り消し UI の不在 | `monthly-closing.md` D-4・AC-6 |
| AC-5 | 空月・未入力日を含む月の締め | `monthly-closing.md` AC-7 |
| AC-6 | 締めが弾かれる場合の表示 | 共通仕様 AC-6 |
| AC-7 | 限界 | — |

### AC-1. 締めボタンの提供条件

| # | 状態・操作者 | 期待 |
|---|---|---|
| 1-1 | `Draft` かつ技術者本人 | 締めの操作要素を**提供する**（`monthly-closing.md` AC-1-1・AC-2-1） |
| 1-2 | `Draft` かつ本人以外（他の技術者・承認者） | 締めの操作要素を**提供しない**（`monthly-closing.md` AC-2-2・AC-2-3） |
| 1-3 | `PendingApproval` / `Approved` | 締めの操作要素を**提供しない**（二重締め・終端。`monthly-closing.md` AC-1-2・AC-1-3） |
| 1-4 | 締め可能なタイミング | 月末・月途中を問わず提供する（月末制約を UI に課さない。`monthly-closing.md` AC-1-4・D-3） |

### AC-2. 締め確認ステップ

締めは取り消せない（`monthly-closing.md` D-4）ため、実行前に確認を挟む。

| # | 条件 | 期待 |
|---|---|---|
| 2-1 | 締めの実行 | 実行前に確認ステップを設け、締めが取り消せないこと（下書きへ戻す手段は承認者の差戻しのみ）を利用者に伝える |
| 2-2 | 確認で承諾 | 締めを実行し、AC-3 の帰結へ進む |
| 2-3 | 確認で中断 | 締めを実行せず、`Draft` のまま画面へ戻る（状態を変えない） |

> 確認ステップの具体的表現（モーダル等）は ADR 0015 のデザイン工程が担う。本 AC は「取り消せない旨を提示して確認を取る」ことのみ要求する。

### AC-3. 締め後の帰結表示

| # | 締め成立後 | 期待 |
|---|---|---|
| 3-1 | 状態バッジ | `PendingApproval` を表示する（`monthly-closing.md` AC-5-1） |
| 3-2 | 超過／不足 | 締め時に算出・保存された超過／不足を表示する（共通仕様 AC-4-2）。少なくとも一方は 0（`monthly-closing.md` AC-3-4） |
| 3-3 | 稼働実績 | 入力・編集・削除を提供しなくなる（read-only。共通仕様 AC-5-1） |
| 3-4 | 総稼働時間・精算幅 | 引き続き表示する（`monthly-closing.md` AC-5-3） |

### AC-4. 締め取り消し UI の不在

| # | 条件 | 期待 |
|---|---|---|
| 4-1 | `PendingApproval` の勤務月 | 技術者に「締めを取り消す／下書きへ戻す」操作要素を**提供しない**（`monthly-closing.md` D-4・AC-6-1） |
| 4-2 | 下書きへ戻す導線 | UI 上に存在させない。下書きへ戻るのは承認者の差戻し（`approval-ui.md`）の結果としてのみ（`monthly-closing.md` AC-6-2） |

### AC-5. 空月・未入力日を含む月の締め

| # | 条件 | 期待 |
|---|---|---|
| 5-1 | 一部の日が未入力の勤務月（`Draft`・本人） | 締めボタンを提供する（未入力を理由に締めを妨げない。`monthly-closing.md` AC-7-1） |
| 5-2 | 実績が1件も無い勤務月（空月。`Draft`・本人） | 締めボタンを提供する（`monthly-closing.md` AC-7-2） |
| 5-3 | 未入力日 | 締め時に未入力の警告・確認を出さない（判定不能なため。`monthly-closing.md` AC-7-3） |

### AC-6. 締めが弾かれる場合の表示

| # | 条件 | 期待 |
|---|---|---|
| 6-1 | 締め操作が業務ルールで弾かれた（既に締め済等の競合） | 現在の状態を反映し直し、理由を提示する（共通仕様 AC-6-4）。二重に締めない |

### AC-7. 限界 — 本仕様が担保しないこと

| # | 内容 |
|---|---|
| 7-1 | 承認・差戻しの UI は対象外（`approval-ui.md`） |
| 7-2 | 超過／不足は時間側の量として表示する。**精算金額を表示しない**（`monthly-closing.md` AC-8-4） |
| 7-3 | 「誰がいつ締めたか」の履歴を表示しない（監査履歴は非スコープ。`monthly-closing.md` AC-8-3） |
| 7-4 | デザイントークン・確認ステップの具体表現は ADR 0015 のデザイン工程が担う |
