# 稼働の推移 — UI/画面 仕様

ADR 0021 決定1 が加えた閲覧系の画面「稼働の推移」の UI/画面 受け入れ条件。技術者が**自分の**勤務月について、契約ごとに月々の総稼働時間と精算幅を見比べる画面である。勤務月の集約をまたいで読む参照系の関心事であり（ADR 0021 決定2）、新しい状態も新しい操作も加えない。

業務ルール・ユビキタス言語は**この仕様へ書き写さない**ものとする。正解は ADR 0021 決定2、各業務仕様、`docs/domain/ubiquitous-language.md`。本仕様は「稼働の推移の画面が満たすべき形」だけを定める（ADR 0004）。

本仕様は、ユビキタス言語「稼働の推移で使う語」の「確定した月」「入力中」「精算幅に収まった月」を使う。いずれも 2026-10-10 に人間が確定した語である。

- **決定者**: 人間（プロジェクトオーナー）。画面があること・自分の勤務月だけを見ること・確定した月と入力中の区別・平均と「精算幅に収まった月」の数から入力中を外すこと・月ごとに比べる精算幅を各勤務月が写し取った値とすること・平均を利用者が選んだ期間の確定した月で求めその表記を定めたことは人間決定（ADR 0021 決定1・決定2）。超過・不足を赤（`--danger`）で示すこと（`design-system.md` D-2-12・AC-2-3）と、そのロールで開けない画面を開いたときにそのロールの既定の画面へ移すこと（条文の正は `login-ui.md` AC-6-7〜6-9-b）は、2026-10-10 の人間決定である。平均の桁数と端数の扱い（ADR 0021 決定2）と、小数第1位が 0 になる平均の表記（4-1-e）と、不足の月の棒を全体まで赤にすること（5-4(ii)）は、2026-10-13 の人間決定である
- **日付**: 2026-10-10（2026-10-13 改定: 2026-10-10 の人間決定を反映し、比べる精算幅・平均・超過と不足の色・開けないロールが開いたときの扱いを定め、未確定点を解消。同日の人間決定を反映し、平均の期待値の例 4-1-d と、5-4(ii) の不足の月の棒・勤務月画面 AC-4-6 との関係 5-4-b を定めた。同日の人間決定により、AI 起案の箇所をすべて人間の承認済みへ改めた。同日の人間決定を反映し、小数第1位が 0 になる平均の表記 4-1-e を確定し、4-1-d に例 (f) を足して、残存する未確定点を無くした）
- **前提 ADR**: 0021（閲覧系の画面・元データ）／0016（認証・ロール・ゲスト）／0015（デザイン工程）
- **AI 起案の扱い**: 条文中に「AI 起案（2026-10-13 に人間が承認）」と書いた箇所は、AI が起案し、2026-10-13 に人間が一括で承認したものである。承認済みであり、その箇所をテストの期待値にしてよい

## スコープ

- **対象**: 推移に載せる勤務月の範囲、月の区分（確定した月・入力中）、契約と期間の選択、要約（平均・精算幅に収まった月・精算幅）、月ごとの総稼働時間の図、超過・不足を赤で示す要素、閲覧のみであること、開ける利用者、空状態・エラー
- **非対象**:
  - 超過・不足の算出そのもの（`monthly-closing.md` AC-3・AC-4 が持つ。本画面は算出の規則を持たず、締め時に保存された値を読む）
  - 平均の算出と表記の規則（ADR 0021 決定2 が持つ。本仕様は書き写さない。AC-4-1-a）
  - 契約の管理・契約のデータの投入（`contracts-ui.md` の非対象と同じ。ADR 0021 決定1・決定2）
  - サイドバーの項目（`work-month-listing-ui.md` AC-10 が持つ）・ヘッダー（`login-ui.md` AC-9 が持つ）
  - そのロールで開けない画面から既定の画面へ移すこと（`login-ui.md` AC-6-7〜6-9-b が持つ。本仕様は稼働の推移に当てはめた結果だけを AC-7 に示す）
  - 技術者の横断ビュー・承認担当者一覧（他の技術者の稼働を見る画面。非スコープのまま。ADR 0021 決定1／ユビキタス言語「MVP スコープ外」）
  - 精算金額（算出しない。`monthly-closing.md` AC-8-4）
  - デザイントークン・具体レイアウト（`design-system.md`）

### AC-3. 期間

平均が利用者の選んだ期間に従うことは人間決定である（ADR 0021 決定2「平均は、利用者が選んだ期間の確定した月の総稼働時間を平均したもの」「期間の選び方と表記の細部は稼働の推移の UI 仕様が持つ」）。期間の既定・選択の欄の形は AI 起案であり、2026-10-13 に人間が承認した。

| # | 条件 | 期待 | 決定の別 |
|---|---|---|---|
| 3-1 | 期間の既定 | 選んだ契約の勤務月（1-5）のすべてを含む期間とする（開始は最も古い対象年月、終了は最も新しい対象年月）。月数の上限を固定しない | AI 起案（2026-10-13 に人間が承認。ハンドオフに倣った） |

| 3-3 | 終了の選択肢 | 開始と同じかそれより後の対象年月だけを出す。開始を終了より後へ変えたときは、終了を開始と同じ年月にそろえる | AI 起案（2026-10-13 に人間が承認。ハンドオフに倣った） |

### AC-4. 要約（平均・精算幅に収まった月・精算幅）

| # | 条件 | 期待 | 決定の別 |
|---|---|---|---|
| 4-1 | 平均の対象 | 平均は、選んだ期間（3-6）の確定した月（2-1）の総稼働時間だけを対象にし、入力中の月（2-2）と期間の外の月を含めない | 人間決定（ADR 0021 決定2） |
| 4-1-a | 平均の算出と表記 | ADR 0021 決定2 の定めに従う（総稼働時間を平均し、時間を単位とする小数で示す。桁数と端数の扱いは同決定の字面が正であり、本仕様は書き写さない）。テストの期待値は同決定から導く | 人間決定（ADR 0021 決定2。桁数と端数の扱いは 2026-10-13 に人間が確定） |

| 4-1-e | 小数第1位が 0 になる平均の表記 | 平均を丸めた値の小数第1位が 0 になるときも、小数第1位の `0` を省かず、常に小数点以下1桁を示す（例: `160.0`。`160` と示さない）。テストの期待値にしてよい（4-1-d の (f)） | 人間決定（2026-10-13。ADR 0021 決定2 が「表記の細部は稼働の推移の UI 仕様が持つ」としたものを定めた） |
| 4-1-b | 平均の見出し | `平均稼働（確定した月）` | AI 起案（2026-10-13 に人間が承認。ハンドオフに倣った） |
| 4-1-c | 平均の単位の表示 | 値に単位 `時間` を添える | AI 起案（2026-10-13 に人間が承認。ハンドオフに倣った） |
| 4-2 | 確定した月が0件 | 平均を数値で示さない（`0` と示さない）。値が無いことを文字で示す | AI 起案（2026-10-13 に人間が承認） |
| 4-3 | 精算幅に収まった月の数 | 確定した月のうち、超過も不足も生じていない月を数えて示す。入力中の月を数えない。あわせて確定した月の数を示す（例: `9 / 11 か月` は確定した月 11 のうち 9 が収まった） | 数えるものは人間決定（ADR 0021 決定2）。確定した月の数を添える表し方は AI 起案（2026-10-13 に人間が承認。ハンドオフに倣った） |
| 4-3-a | 収まったかの判定 | 確定した月ごとに、締め時に勤務月へ保存された超過と不足（`monthly-closing.md` AC-3）を読み、両方が 0 の月を収まった月とする。判定に使う精算幅は、その勤務月が写し取った精算幅である（P-10）。契約のいまの精算幅を読まず、本画面で超過・不足を算出し直さない | 比べる精算幅は人間決定（ADR 0021 決定2）。保存された値を読むことは、同決定の「締め時に保存された値と一致する」と非対象（算出の規則を持たない）からの帰結 |

| 4-4-a | 期間の月の精算幅がすべて同じ | その精算幅の下限と上限を1つ示す | AI 起案（2026-10-13 に人間が承認） |

### AC-5. 月ごとの総稼働時間の図

### AC-9. 限界 — 本仕様が担保しないこと

| # | 内容 |
|---|---|
| 9-1 | 入力中の月は平均と数から外れるため、月の途中で見る推移の要約は、直近の月を含まない（ADR 0021「悪い影響 / トレードオフ」） |
| 9-2 | 推移を描くのに要るデータ（本人の勤務月ごとの総稼働時間・写し取った精算幅・締め時に保存された超過／不足・状態）を一度に読む口は、本仕様の時点の `domain-api-http-contract.md` に無い。勤務月一覧（同 AC-3。E-2）の行は契約識別子・契約表示名・年月・状態だけを持ち（同 AC-3-9）、総稼働時間・精算幅・超過／不足を持たない。読む口の形（E-2 の行を広げるか、新しい参照のエンドポイントを設けるか、BFF が勤務月の取得 E-1 を月の数だけ呼ぶか）は、両仕様（`domain-api-http-contract.md`・`workmonth-implementation-design.md`）の改定として別に起こす。どの形でも、読む精算幅は勤務月が写し取った値であり、契約のいまの値ではない（P-10） |
