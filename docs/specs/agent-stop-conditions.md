# 工程エージェントの停止条件 — 「一線」を tester / implementer の資産にする

Issue #92 の仕様。ADR 0018 決定2（一線を停止条件へ恒久化する）を、`.claude/agents/tester.md` / `.claude/agents/implementer.md` が満たすべき**受け入れ条件**に落とす。根拠は `docs/adr/0018-public-api-diff-warning-and-stop-condition.md`。

**決定の本文（なぜ恒久化するのか・なぜ指示文の強化では足りないのか）はこの仕様へ書き写さない。** 正解は ADR 0018 にあり、本仕様はそれを参照して「エージェント定義が満たすべき形」だけを定める（ADR 0004）。

**停止条件の追加は ADR 0010 §A で人間の承認事項にあたるが、その承認は ADR 0018 決定2 が記録済みである。** 本仕様は承認を新たに取り直さないし、承認範囲を広げもしない。承認されたのは「一線を上記2ファイルの停止条件へ書くこと」であり、それ以外の停止条件の新設・変更・削除は本仕様の対象外である。

---

## スコープ

`.claude/agents/tester.md` と `.claude/agents/implementer.md` の**停止条件の節**に、一線を1項目として追加すること、および既存項目が維持されていることの判定基準までを対象とする。

### 非スコープ

- **ADR 0018 決定1（CI の公開 API 差分警告）**。Issue #92 の完了条件は決定2 のみを対象とする。チェッカ・CI step・trailer（`Approved-API-Change:`）は本仕様の対象外であり、別の作業で扱う
- **他のエージェント定義**（`specifier.md` / `reviewer.md` / `orchestrator.md`）への一線の追加。ADR 0018 決定2 が名指しするのは2ファイルのみであり、広げる判断は人間の決定事項（ADR 0010 §A）
- **既存の停止条件の文言変更・統合・削除**。AC-2 は維持だけを求める
- **`make` ターゲット・CI step の新設**（AC-4-6 / U-1 の決定を参照）。本仕様は判定基準を定めるが、検査手段は新設しない
- 工程エージェントが実際に停止したかの計測（AC-4-3。振る舞いは artifact に残らない）

---

## 前提（P）

### P-1. 一線の正本は ADR 0018 のコンテキスト節にある

一線の文そのものは ADR 0018「コンテキスト」節の引用が正本である。**本仕様が下に掲げる文字列は、その正本を検査可能にするための判定基準であって、決定の再掲ではない。** 食い違いが生じた場合は ADR 0018 側が正であり、本仕様の判定基準を追随させる。

**検査対象が文言そのものである以上、判定基準を字面で持たなければ「入っていること」を判定できない。** ADR 0004 が禁じるのは決定・理由を docs 外や別の docs へ書き写して二重管理を作ることであり、検査基準の明示はこれに当たらない（`docs/specs/orchestrator-entry-hook.md` が検知パターンの単一情報源であるのと同型）。

### P-2. 停止条件はプロンプト資産であり、参照では代替できない

`docs/specs/skills.md` AC-4 は「Skill 本文は docs を参照し、手順本文をコピーしない」と定める。**停止条件はこれと扱いが異なる。** 工程エージェントが停止するかどうかは、そのエージェント定義が読まれた時点の文言で決まる。参照リンクだけを置いても、リンク先を読む保証はない。したがって**一線の文言は2つのエージェント定義に実体として置く**（AC-1）。増やしてよいのはこの2箇所までとし、それ以外への転記は禁じる（AC-3-3）。

## 受け入れ条件（AC）

| AC | 主題 | 主に効く工程 |
|---|---|---|
| AC-1 | 一線を両ファイルの停止条件節へ、判定可能な形で追加する | implementer・reviewer |
| AC-2 | 既存の停止条件を1項目も消さない・変えない | tester・reviewer |
| AC-3 | 根拠として ADR 0018 を節内から参照し、文言をそれ以上増やさない | implementer・reviewer |
| AC-4 | 機械検査できる範囲と、規律に留まる範囲を分けて固定する | tester・reviewer |

### AC-1. 一線を停止条件節へ追加する

#### 1-1. 対象ファイルと対象節

| # | 対象 |
|---|---|
| 1-1-a | `.claude/agents/tester.md` |
| 1-1-b | `.claude/agents/implementer.md` |

**対象節は、行頭が `## 停止条件` で始まる見出し行から、次の行頭 `## ` 見出しの直前まで**とする。両ファイルとも `## 停止条件` で始まる見出しは1つだけであり、これが節の同定手段になる。見出し行そのものを書き換えない。

#### 1-2. 追加する項目の判定基準

対象節の本文が、次の**連続した部分文字列**を含むこと。

```
新しい名前・新しい公開 API・新しい差し替え点を作る必要が出たら、書く前に停止して報告する
```

- 区切りは**中黒 `・`**（読点やスラッシュに置き換えない）
- `公開 API` の前後は**半角スペース1個**（`公開API` や全角スペースは一致しない）
- 読点は**全角 `、`**
- 末尾の句点 `。` と、直後に続く根拠参照（AC-3）は、この部分文字列の外側に置いてよい
- 強調記号（`**`）を文中に挟まない。挟むと連続した部分文字列として一致しなくなる。強調するなら文全体を囲む

**部分文字列の完全一致で判定するのは、言い換えを許すと「何をもって入っていると見なすか」が判定者ごとに変わるためである。** 一線は Issue #89 で2回連続して破られており、その再発防止として恒久化する以上、判定基準そのものを揺らがせない。

#### 1-3. 項目の形と位置

| # | 要求 |
|---|---|
| 1-3-a | 対象節の**箇条書き項目**（行頭 `- ` で始まる行）として置く。散文の段落に混ぜない |
| 1-3-b | **1行で書く**（途中で改行して複数行に折らない）。行単位で判定できる形を保つ |
| 1-3-c | 既存項目の**末尾に追加する**。既存項目の順序を入れ替えない |
| 1-3-d | 両ファイルで**同一の文言**を使う。片方だけ言い回しを変えない |

1-3-c は「追加であって改変ではない」ことを差分の形で読めるようにするためである（ADR 0018「良い影響」1点目が、緩めた場合に差分として説明を要することを前提にしている）。

### AC-2. 既存の停止条件を消さない・変えない

**この表が「維持すべき項目」の単一情報源である。** 各行は、対象節に**その行の文字列がそのまま**存在することを要求する（行頭の `- ` を除いた本文の完全一致）。

維持すべき項目は、下の**行そのもの**（強調記号・バッククォート・句読点を含む）である。読みやすさのために書き換えない。

#### 2-1. `.claude/agents/tester.md`（3項目。2-1-a 〜 2-1-c）

```
- 仕様に無い業務ルールをテストの期待値に埋める必要が出た。
- 期待値が仕様から一意に定まらない（複数解釈できる）。
- 標準 + go-cmp で表現できず、ライブラリ追加が要ると感じた（許可リストの変更は人間の承認事項）。
```

#### 2-2. `.claude/agents/implementer.md`（4項目。2-2-a 〜 2-2-d）

```
- 通すために仕様に無い業務ルールの判断が要った。
- 通すために**層を増やす／減らす**必要が出た（人間の承認事項）。
- 通すために `domain` の許容 import やコストガードレールを緩める必要が出た。
- 同一失敗の再試行が上限に達した（`docs/harness/verification-loop.md`「ループの上限値」の既存停止条件。実装↔レビュー往復の上限とは別物）。
```

**2-2-d は数値（上限回数）を書き写していない。** 上限値は `docs/harness/verification-loop.md` を唯一の定義箇所とする（DRY）。この形を崩して数値を項目へ埋め込まない。

#### 2-3. 節末の締めの文も維持する

停止条件の節は、箇条書きのあとに「推測で埋めない」旨と「停止はオーケストレーター経由で人間へ上がる」旨の段落を持つ。**この段落を削らない・弱めない。** 判定基準は、対象節が次の部分文字列をいずれも含むことである。

| # | ファイル | 含むべき部分文字列 |
|---|---|---|
| 2-3-a | tester | `推測で期待値を埋めない` / `停止はオーケストレーター経由で人間へ上がる` |
| 2-3-b | implementer | `推測で業務ルールを埋めない` / `停止はオーケストレーター経由で人間へ上がり、握り潰されない` |

#### 2-4. 項目数

追加後の箇条書き項目数は、**tester が4項目、implementer が5項目**（既存 + AC-1 の1項目）とする。

- **項目数を固定するのは、追加に紛れて別の項目が増減することを差分レビュー以外でも検知できるようにするためである**（ADR 0010 §A が「改善と弱体化は同じ観測結果を生む」と述べた問題への対処）
- 将来、人間が承認した別の停止条件を足す場合は、**同じ変更で AC-2 の表と本項の数値を更新する**。数値だけを実装側で動かさない。停止条件の増減は人間の承認事項である（ADR 0010 §A）

### AC-3. 根拠の参照と、文言を増やさないこと

| # | 要求 |
|---|---|
| 3-1 | 対象節が部分文字列 `docs/adr/0018` を1つ以上含むこと。ADR のファイル名全体（`docs/adr/0018-public-api-diff-warning-and-stop-condition.md`）で書いても、既存の短縮形（`docs/adr/0007` と同じ形）で書いてもよい。**参照は AC-1 の項目と同じ節の中に置く**（別の節に置くと、節だけを読む工程エージェントに根拠が届かない） |
| 3-2 | **ADR 0018 決定1 に属する記述を両ファイルへ持ち込まない。** 判定基準は、両ファイルが文字列 `Approved-API-Change` を含まないこと、および公開 API 差分の CI 警告・verdict（`OK` / `WARN` / `SKIP` / `INDETERMINATE`）の運用説明を持たないこと。決定1 は Issue #92 のスコープ外であり、停止条件と混ぜると「警告が出たら止まる」と読み替えられる（**一線は警告の有無と無関係に、書く前に止まることを求めている**） |
| 3-3 | **一線の文言を、この2ファイル以外へ転記しない。** `docs/rules/` / `CLAUDE.md` / 他のエージェント定義 / Skill へコピーを作らない。正本は ADR 0018、検査基準は本仕様であり、実体は P-2 の理由により2ファイルに限って置く |

3-2 の後段（verdict の運用説明を持たないこと）は字面での完全な機械判定に馴染まない。**ここはレビュー工程が持つ**（AC-4-4）。

### AC-4. 機械検査できる範囲と、規律に留まる範囲

**検査できるのは「エージェント定義に文言が入っていること」までである。** 工程エージェントが実際にその場面で停止するかは、この仕様では機械検査しない。両者を混同すると、「文言を入れたので一線は守られる」という、Issue #89 の実測に反する読み方が生じる。

| # | 内容 |
|---|---|
| 4-1 | **AC-1 の文言の存在は機械検査しうる。** 対象節を切り出し、1-2 の部分文字列を含むかを判定するだけで足りる（`docs/specs/notation-rules.md` AC-5-1「キーワードの存在までは検査しうる」と同型） |
| 4-2 | **AC-2 の維持も機械検査しうる。** 維持すべき項目は AC-2 の表が単一情報源であり、行単位の完全一致と項目数で判定できる。**「消していないこと」は、消えた側で赤くなる形でしか固定できない**（`docs/specs/issue-command.md` AC-8-13 と同じ理由。通る側だけを見る検査は、何も見ていなくても緑になる） |
| 4-3 | **工程エージェントが実際に停止するかは機械検査しない。** 停止は振る舞いであり、artifact に痕跡が残らない（`docs/rules/notation.md`「機械検査の限界」、`docs/harness/verification-loop.md`「artifact に残らないものは検査できない」と同型）。**しかも Issue #89 の実測は「指示文を強化した直後に再発した」ことを記録している。文言の存在は遵守を意味しない。** 担保は規律に留まり、ADR 0018「限界」3 が列挙する `no-spec` / `loop-extended` / `[direct]` と同じ列に並ぶ |
| 4-4 | **AC-3-2 の後段（決定1 の運用説明を混ぜないこと）は、字面の禁止語（`Approved-API-Change`）を超える範囲では機械検査しない。** 言い換えられた説明文を機械が同定できないためである。受け皿はレビュー工程と、本仕様の非スコープの明示 |
| 4-5 | **本仕様は検査手段（`make` ターゲット・CI step）を新設しない**（非スコープ）。**したがって現時点の担保は、AC-1〜AC-3 を満たす差分をレビュー工程が読むことと、ADR 0018 が承認の記録を持つことに留まる。** 4-1 / 4-2 は「検査しうる」であって「検査している」ではない（`docs/specs/notation-rules.md` AC-5 と同じ位置づけ） |
| 4-6 | **4-5 を検査手段の新設で埋めるかは決定済みである。決定者は人間、決定内容は (a) 新設しない**（2026-09-07、AskUserQuestion による明示選択）。したがって 4-5 の担保のとおり、差分レビューと ADR 0018 の記録に留める。選択肢と論点、および決定を将来改める場合の手順は下の「決定事項」節 U-1 に置く。**AI がこの決定を本仕様の側で動かさない** |

**「一線を停止条件へ書いたので一線は守られる」と読める AC を後から足さないこと。** 文言の存在が保証するのは、破られたときに**何が破られたのかを字面で指させる**ことだけである。

## 決定事項

### U-1. AC-1〜AC-3 を機械検査へ載せるか — **(a) 新設しない**（決定済み）

**決定の記録。** 決定者は**人間**、決定日は **2026-09-07**、決め方は **AskUserQuestion による明示選択**。選ばれたのは下表の **(a) 新設しない**である。**この決定は AI の推定ではなく、人間が選択した事実の記録である。**

**Issue #92 の完了条件は3つとも「エージェント定義の内容」であり、検査手段の新設を求めていない。** 一方、本リポジトリは「規律に頼る規約は腐る」を前提に検査を足してきた。どちらに倒すかは停止条件そのものの扱いに関わるため、人間の決定事項とした（ADR 0010 §A）。

**(a) を選んだのは、Issue #92 の完了条件を越えないためであって、(b) / (c) が案として劣ると判断したからではない。** (b) / (c) は却下されていない。

| 案 | 内容 | 論点 |
|---|---|---|
| **(a) 新設しない**（**採用**） | AC-4-5 のとおり、差分レビューと ADR 0018 の記録に留める | Issue #92 の完了条件と一致する。`docs/specs/notation-rules.md` AC-5 と同じ位置。**ただし、後から AI が一線を静かに削っても CI は緑のまま**である |
| **(b) 実対象の検査を新設する** | `check-agent-stop-conditions`（実 `.claude/agents/*.md` の検査）と、その fixture（`test-agent-stop-conditions`）を2ターゲット立てで作り、既存 CI ジョブ `Scripts (checker logic)` へ step を追加する | `check-skills` / `test-skills` と同じ形であり、**ruleset `protect-main` への必須チェック追加登録（人間のブラウザ操作）は発生しない**（ADR 0018 決定6 と同じ理由で新規ジョブを起こさない）。代償は、停止条件の文言がチェッカ側にも現れること（AC-2 の表が単一情報源である旨をチェッカのコメントで明示して抑える） |
| **(c) 既存の `check-skills` を拡張する** | 対象に `.claude/agents/` を足す | `docs/specs/skills.md` AC-5 が定めた `check-skills` の契約（対象は `.claude/skills/*/SKILL.md`）を変えることになり、**別仕様の書き換えを伴う**。対象種別が違うものを1つのターゲットに合流させる点でも、`test-hooks` を `test-scripts` に合流させなかった判断（`docs/specs/orchestrator-entry-hook.md`「対象」節）と逆行する |

**(b) を将来採る場合は、Issue を分けて起票し、本仕様の AC-4-5 / AC-4-6 を同時に現況へ改める。** 本項の決定をそのまま上書きせず、(a) から (b) へ移した旨と、その決定者・日付を残す。**採否を変える判断は人間の決定事項である**（ADR 0010 §A）。

**この決定は AC-1〜AC-3 の要求水準を下げない。** 決まったのは検査手段を新設しないことだけであり、判定基準（AC-1-2）・維持すべき項目と項目数（AC-2）・参照と転記禁止（AC-3）はそのまま要求として残る。AC-4-3 が固定した限界（実際に停止するかは機械検査せず、担保は規律に留まる）も変わらない。
