# ループの作業記憶（メモリ機構 / Context）

ハーネスエンジニアリングの5構成要素のうち **Context** を満たす動的な側面がこれである。静的な規約（Rules）は `docs/rules/` に切り出した（ADR 0010 §B）。ここで扱うのは、ループが回るあいだに溜まる**使い捨ての作業記憶**である。決定の根拠は `docs/adr/0010-harness-engineering.md` §Context。

## なぜ作業記憶が要るのか

AI の試行錯誤は、セッションが終われば消える。次のループは、前のループが「何を試して、なぜ失敗したか」を知らないまま同じ轍を踏む。フィードバックループが速くても、**経緯が残らなければ学習は積み上がらない**。

そこで、進捗・過去のエラーログ・試行錯誤の履歴を `progress.md` に書き出し、次以降のループが読み込めるようにする。これは Rules（静的な規約）とは別物で、**動的なプロセス状態**を持つ。

## 格納するもの / 格納しないもの

| | 置き場所 |
|---|---|
| **格納する** — 進捗、直近のエラーログ、試したことと失敗の原因、次の一手 | `progress.md`（ローカル・gitignore 済み） |
| **格納しない** — 決定した仕様・設計・受け入れ条件 | `docs/`（従来どおり） |

`progress.md` は**プロセス状態のみ**を持つ。決定した仕様をここに書き写さない。書き写した瞬間、`docs/` との二重管理が生まれ、ADR 0004 が回避しようとした状態に戻る。

## 優先順位 — `docs/` > `progress.md`

**食い違ったら常に `docs/` が正しい。** これは ADR 0004 の「Issue コメントは docs より優先されない」と同じ構造である。

この順位を欠くと、メモリ機構は新たな失敗モードを持ち込む。すなわち「**古くなった作業記憶を、次のループが正しいと信じて実装する**」——このリポジトリが最も警戒する陳腐化である。`progress.md` は足場であって正解ではない。仕様の確認は必ず `docs/` に戻って行う。

## ライフサイクル — ローカル保持、タスク完了 / PR マージで破棄

- `progress.md`（および `.harness/` 配下の補助ログ）は **`.gitignore` 済み**。リポジトリ履歴を汚さない。
- **タスク完了 / PR マージの時点で破棄する。** 使い捨てに徹し、次のタスクへ持ち越さない。持ち越すと陳腐化リスクがそのまま残る。
- **恒久的に残すべき証跡は `progress.md` に溜めない。** ループの経緯・往復の要約は **PR コメント**に残す（ADR 0010 §C）。`progress.md` が消えても、証跡は PR に残る、という分担にする。

> **なぜ commit しないのか。** 作業記憶を履歴に載せると、(1) 古い進捗が git blame に永久に残り、(2) `docs/` との二重管理を履歴レベルで作ってしまう。`progress.md` は「今このループが立っている足場」であって成果物ではない。成果物は `docs/`（仕様・設計）と PR コメント（証跡）に出す。

## フォーマットと開始手順

- ひな形は `docs/harness/progress-template.md`（これは commit される）。
- ループを始めるとき、ひな形をリポジトリ直下 `progress.md` へコピーして書き始める。
- 補助的なエラーログや長い試行履歴が要る場合は `.harness/` 配下に置く（同じく gitignore 済み）。

## 誰が読み書きするか

- **オーケストレーター**が既定の入口として、ループの開始時に `progress.md` を読み、工程の区切りで更新する（`docs/adr/0010-harness-engineering.md` §D）。
- 各工程エージェント（specifier / tester / implementer / reviewer）は、必要に応じて `progress.md` の「試したこと・失敗ログ」を参照・追記する。ただし**仕様の確認は必ず `docs/` に戻る**（優先順位）。

## この機構が守れないこと

正直に記録しておく。**ライフサイクルの運用が緩めば、陳腐化の失敗モードは再発する**（ADR 0010 §影響）。「タスク完了で破棄」を守るのは人間と AI の規律であり、機械的な強制はない。`.gitignore` が担保するのは「履歴を汚さないこと」だけで、「古い記憶を破棄すること」までは強制しない。優先順位（`docs/` > `progress.md`）は、この規律が緩んだときの最後の安全弁である。
