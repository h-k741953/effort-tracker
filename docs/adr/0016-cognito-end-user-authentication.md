# 0016. エンドユーザー認証に Amazon Cognito を採用する

- **ステータス**: 承認済み
- **日付**: 2026-07-23
- **決定者**: 人間（プロジェクトオーナー）

## コンテキスト

当初、UI 仕様（`docs/specs/work-month-screen-ui.md` Q3）は「現在ユーザー／ロールの決定」を未確定とし、`docs/rules/scope.md` は**ユーザー・ロール管理を MVP 非スコープ**としていた。デモを公開するにあたり、認証をスタブで済ませるか実基盤を入れるかを判断する必要が生じた。

ポートフォリオとして「実運用に耐える認証」を示す価値は高い。一方、デモは公開 URL であり、**コストとセキュリティのガードレール（$5 予算・静的キー禁止・OIDC）は機能要件と同格**（CLAUDE.md／`docs/rules/cost-guardrails.md`／`docs/rules/security.md`）。したがって認証基盤は次で評価する。

- **AWS ネイティブ方針（ADR 0013 / 0014）と整合**すること。別 SaaS 依存を増やさない
- **$5 予算を濫用で溶かさない**こと（公開デモは認証コード送信等の濫用ベクタになる）
- **静的な長期認証情報を置かない**方針（`docs/rules/security.md`）と衝突しないこと
- 既存の**サービス間認証**（ADR 0003 Function URL の IAM 認証、ADR 0014 BFF 実行ロール）とレイヤーが異なることを明確に保つこと

## 決定

**エンドユーザー認証に Amazon Cognito（User Pool）を採用する。** ログインは3方式を提供する。

1. **ゲスト**（未ログイン）= **閲覧のみ**。Cognito のユーザーを作らず、未認証状態として扱う（MAU を消費しない）。状態を変える操作は提供しない（`work-month-screen-ui.md` AC-3 のゲスト行）
2. **メールアドレス + パスワード**（新規登録・ログイン）。**MFA は TOTP（認証アプリ）**を採用する
3. **Google 連携**（OIDC ソーシャルサインイン）

### 認証と認可・レイヤーの分界

- Cognito は**本人確認（認証）**を担う。`Engineer` / `Approver` の**ロール（認可）**は別問題であり、**デモ用に切替可能**とする（ロール管理画面は作らない。`scope.md` の非スコープを維持）
- **自己承認排除（`approval.md` D-4）はロールに依存せず維持**する
- エンドユーザー認証は **BFF（Next.js Route Handler）で終端**する。BFF が Cognito 発行のトークンを検証し、そこから先のドメイン API 呼び出しは**従来どおり実行ロールの SigV4 署名**（ADR 0014）。**ADR 0003 / 0014 はサービス間認証で別レイヤーであり、本 ADR は置換しない（併存）**

## 影響

### 良い影響

- **実運用に耐える認証をポートフォリオで示せる**（MFA・ソーシャルログイン・ゲスト体験）
- **AWS ネイティブ方針に一貫**（ADR 0013 / 0014 と揃う。別 SaaS を増やさない）
- **TOTP により MFA の追加コストが0**。濫用による従量課金の経路を持たない（$5 予算と両立）
- **ゲストを未認証扱い**にすることで、体験導線を保ちつつ MAU コストと書き込みリスクを避ける

### 悪い影響 / トレードオフ

- **Cognito への依存とコスト**。User Pool の MAU は無料枠を超えると従量課金（正確な料金は実装時に要確認）。デモは日次リセット・少数ユーザー前提で無料枠内を想定
- **Google OAuth のクライアントシークレットという機密が増える**。コミットしない（`terraform.tfvars` は gitignore 済み／`docs/rules/security.md`）。静的 AWS キーではないが機密として扱う
- **TOTP は利用者に認証アプリ導入の手間**を強いる（SMS を避けた代償）
- **ロール切替をデモ用に持つ**ことは本番の権限設計そのものではない。線引きを `scope.md` に明記する必要がある

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| 認証スタブ（固定ユーザー） | 実運用の認証を示せない。ポートフォリオ価値が低い |
| SMS による MFA | 1通ごとに従量課金。公開デモで濫用されると $5 予算を溶かす（`cost-guardrails.md` と衝突） |
| Auth0 / Clerk 等の外部 IDaaS | 別 SaaS 依存とコストが増え、AWS ネイティブ方針（ADR 0013 / 0014）と不整合 |
| 認証を自前実装 | セキュリティ責務を自前で負う。MFA・ソーシャル連携の工数とリスクが過大 |
| ゲストも Cognito ユーザーとして発行 | MAU を消費し、書き込み権限の設計が複雑化。閲覧のみなら未認証で足りる |
