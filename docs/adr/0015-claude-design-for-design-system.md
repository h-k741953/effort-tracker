# 0015. フロントエンドのデザインシステムに Claude Design を採用する

- **ステータス**: 承認済み
- **日付**: 2026-07-23
- **決定者**: 人間（プロジェクトオーナー）

## コンテキスト

MVP のフロントエンドは Next.js（BFF を含め AWS Lambda 上で動く。ADR 0013 / 0014）で構築する。スコープは3ユースケース（稼働実績の入力・編集 / 月次締め / 承認申請・承認。`docs/rules/scope.md`）に限定され、画面数は少ない。まだ `apps/web` は存在せず、コンポーネントライブラリも無い。

このリポジトリはポートフォリオを兼ね、**`docs/` の質はコードと同格の成果物**である（CLAUDE.md）。デザインについても「なぜその UI か」「誰が決めたか」がリポジトリに残ることを重視する。したがってデザインシステムの構築手段も、次の条件で評価する。

- **成果物がバージョン管理に残る**こと（判断の経緯がリポジトリに残らないものは存在しないものとして扱う）
- **AI 駆動の開発フローに組み込める**こと（`docs/specs/` の受け入れ条件 → コンポーネントへの落とし込みを工程として回せる）
- **コストガードレールと矛盾しない**こと（デモ公開の前提。新たな有償 SaaS 依存を増やさない。`docs/rules/cost-guardrails.md`）
- **BFF 経由の一方通行・クリーンアーキテクチャ**などの既存制約を侵さないこと（デザインツールは表現層に閉じ、ドメインへ影響しない）

デザインシステムの構築手段として以下を検討した（詳細は「検討した代替案」）。

- Claude Design（claude.ai/design）+ `DesignSync` による、ローカルのコンポーネントライブラリと design-system プロジェクトの増分同期
- Figma
- Storybook を単独のコンポーネントカタログとして使う
- 生成 AI（v0 等）でのワンショット生成
- 手書きの HTML/コンポーネントライブラリのみ

## 決定

**フロントエンドのデザインシステムを Claude Design（claude.ai/design）で構築し、ローカルのコンポーネントライブラリと `DesignSync` ツールで増分同期する。**

- 正解の実体は **ローカル（リポジトリ内）のコンポーネント成果物**に置き、Claude Design 側はそのミラー／プレビューとして扱う（`docs/` が正解という運用と整合。ADR 0004）
- 同期は **1コンポーネントずつの増分**とし、丸ごと置換はしない
- Claude Design はあくまで**表現層のツール**であり、`domain` / `usecase` には一切影響しない。デザインの決定（採用トークン・コンポーネント一覧・画面遷移）は `docs/specs/` に落とす（SDD。`docs/rules/development-process.md`）
- ローカル成果物の配置先（例: `apps/web` 配下のコンポーネント／`ui_kits/` 等）は、`apps/web` スキャフォールド時に別途確定する

## 影響

### 良い影響

- **デザイン成果物がリポジトリに残る。** Claude Design 単体ではなくローカルを正とするため、コンポーネントが PR レビューとバージョン管理の対象になる（ポートフォリオの「判断が残る」方針と整合）
- **AI 駆動フローに乗る。** `docs/specs/` の受け入れ条件からコンポーネントへ落とす工程を、既存の工程エージェント運用に接続できる
- **追加の有償 SaaS 依存を増やさない。** Figma のような別ツール契約を持ち込まずに済む（コストガードレールと整合）

### 悪い影響 / トレードオフ

- **Claude Design への依存が入る。** 同期機構（`DesignSync` + `/design-sync` スキル）が使えない環境では、ローカル成果物のみで運用する必要がある
- **デザインの「正」の二重化リスク。** ローカルを正とする規律を守らないと、Claude Design 側とローカルが乖離する
- **`/design-sync` スキルが本環境に未インストール。** 当面は `DesignSync` ツールを直接駆動する。スキル前提の運用に寄せるなら別途導入判断が要る

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| Figma | 別 SaaS への依存が増える。成果物がリポジトリ外に出て PR レビュー・バージョン管理に乗りにくい |
| Storybook 単独 | カタログ化はできるがデザインの起草・反復が弱い。Claude Design と排他ではなく、後で併用も可能 |
| 生成 AI でワンショット生成 | 一貫したデザインシステムとして増分管理しにくい。判断の経緯が残りにくい |
| 手書きのみ | 反復が遅く、デザインシステムとしての一貫性を人手で担保し続ける必要がある |
