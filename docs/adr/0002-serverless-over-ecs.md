# 0002. コンテナ常駐構成ではなくサーバーレスを採用する

- **ステータス**: 承認済み
- **日付**: 2026-07-16
- **決定者**: 人間（プロジェクトオーナー）

## コンテキスト

このプロジェクトはポートフォリオであり、**デモURLを README で公開して不特定多数に触ってもらう**ことを前提とする。この前提から、通常の受託案件とは異なる制約が生まれる。

1. **稼働時間のほぼ全てがアイドル**である。デモは散発的にしか叩かれない。月間リクエストは数百〜数千のオーダーを想定する
2. **収益がない**。インフラ費用は自己負担であり、月 $5 を上限とする
3. **無期限に動かし続ける**。案件獲得ツールなので、止まっていると意味がない。「$50/月なら払える」ではなく「毎月払い続けられるか」が問題になる
4. **踏み台にされうる**。公開エンドポイントである以上、悪意あるトラフィックを想定する必要がある（→ ADR 0003）

一般的な Web アプリのリファレンス構成（ALB + ECS Fargate + RDS）を素直に採用すると、**アイドル時にも課金される要素が支配的**になる。

### 常駐構成の概算コスト

ap-northeast-1、リクエストがほぼゼロでも発生する固定費のみを積算した**概算**（2026-07 時点のオンデマンド料金からの見積もり。桁を把握するための数値であり、正式な見積もりではない）。

| 要素 | 概算 / 月 | 備考 |
|---|---:|---|
| NAT Gateway | ~$45 | 時間課金。Fargate から外部へ出るなら実質必須 |
| ALB | ~$18 | 時間課金 + LCU |
| ECS Fargate (0.25vCPU / 0.5GB) | ~$9 | 常時1タスク |
| RDS db.t4g.micro + ストレージ | ~$15 | 無料枠終了後 |
| **合計** | **~$87** | **リクエストがゼロでもこの額** |

月 $5 の予算に対して**1桁以上超過している**。単一要素の削減では届かない。NAT Gateway だけで予算の9倍である。

### サーバーレス構成の概算コスト

| 要素 | 概算 / 月 | 備考 |
|---|---:|---|
| Lambda | $0 | 無料枠（月100万リクエスト / 40万GB秒）内 |
| Lambda Function URL | $0 | 追加課金なし |
| Neon (Free) | $0 | 無料枠 |
| Vercel (Hobby) | $0 | 無料枠 |
| CloudWatch Logs | ~$0〜1 | 保持期間を短く設定 |
| **合計** | **~$0〜1** | |

## 決定

**AWS Lambda (Function URL) + Neon + Vercel によるサーバーレス構成を採用する。**

あわせて、以下を**使用禁止**とする。禁止理由はいずれも「アイドル時課金」である。

- **NAT Gateway** — 単独で予算の9倍。Lambda を VPC 外に置くことで回避する
- **ALB** — Function URL で代替する
- **RDS** — Neon の無料枠で代替する
- **ECS** — Lambda で代替する

この禁止リストは努力目標ではなく、**Terraform のレビュー基準**とする。

### 予算超過の検知

コスト設計は「安く作った」で終わらせず、**破れたことを検知できる**必要がある。

- **AWS Budgets: 月 $5 で2本**
  - 実績 80%（$4）到達で通知 — 既に起きたことの検知
  - 予測 100%（$5）到達で通知 — これから起きることの検知
- **Lambda 予約同時実行数 = 5** — 課金の上限を構造的に固定する（詳細は ADR 0003）

Budgets の2本立てには意味がある。実績通知だけでは、月末に急増した場合に手遅れになる。予測通知だけでは、予測が外れる異常パターン（突発的なスパイク）を拾えない。

## 影響

### 良い影響

- アイドル時のコストが実質ゼロになり、**無期限に公開し続けられる**
- Lambda を VPC 外に置くため、NAT Gateway だけでなく VPC 設計そのものが不要になり、Terraform が小さくなる
- 予約同時実行数により、コストの最悪値が構造的に決まる

### 悪い影響 / トレードオフ

これらは**受け入れる**トレードオフであり、隠さずに README に書く。

- **コールドスタート**が発生する。デモ初回アクセスの体感が悪化する。Go を選ぶことで数百ms程度に収まる見込みだが、ゼロにはならない。Provisioned Concurrency は常駐課金なので**使わない**
- **予約同時実行数 5 が上限**なので、同時アクセスが集中すると 429 が返る。これはコスト保護のための意図的な挙動であり、バグではない
- **Lambda が VPC 外**にあるため、DB 接続はインターネット経由になる。Neon の TLS + 接続文字列に依存する。プライベート接続は使えない
- **コネクションプールと相性が悪い**。Lambda の実行モデル上、Neon 側のプーラー（PgBouncer 互換エンドポイント）に依存する
- **これは本番設計ではない**。実案件でSLAが要求されるなら結論は変わる。この ADR の前提は「収益のないデモを $5/月で無期限公開する」であって、それ以外の文脈に流用してはならない

## 検討した代替案

| 案 | 概算/月 | 却下理由 |
|---|---:|---|
| ALB + ECS Fargate + RDS | ~$87 | 予算の17倍。論外 |
| ECS Fargate + Public IP（ALB/NAT なし） | ~$9 | ALB/NAT は消せるがタスク常駐課金が残り、予算の大半を1要素が食う。Public IP 直公開はセキュリティ上も筋が悪い |
| API Gateway + Lambda | ~$0〜1 | コストはほぼ同等だが、Function URL で足りる要件に対して**リソースが1つ増える**。認証・レート制限は BFF 側で担保するため、API Gateway の機能を必要としない（→ ADR 0003） |
| Vercel Functions のみ（AWS を使わない） | $0 | 最も安い。だが Go / Lambda / Terraform / OIDC という**技術スタックの提示**というポートフォリオ上の目的を失う。ここはコスト以外の理由で却下している |
| Cloudflare Workers | $0 | 同上。加えて Go のサポートが WASM 経由になり、ドメイン層の素直な実装から遠ざかる |

> Vercel Functions のみの構成を「コストのために却下しなかった」ことは明記しておく。この判断は技術デモとしての目的が根拠であり、コスト最適ではない。
